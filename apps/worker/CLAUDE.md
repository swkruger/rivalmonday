# @cs/worker — working notes
The single background worker: pg-boss queues and jobs (collection, engine sweep, briefs, alerts, delivery), Playwright PDF rendering, and the `*-once` CLIs.

## Gotchas
- **Run exactly one replica** — see `docs/gotchas-cross-cutting.md` (per-host rate limiting is in-process).
- **pg-boss 10:** queue names use hyphens; `work()` handlers receive arrays; in production the worker's `DATABASE_URL` is the least-privilege `cs_worker` role (owns schema `pgboss`; migration `0081`) and data goes through `SERVICE_DATABASE_URL` — see `docs/DEPLOY.md` § Roles. Locally it is still the owner URL.
- **cwd-relative dirs:** when run via `pnpm --filter`, `EVIDENCE_FS_DIR=./.evidence` lands in `apps/worker/.evidence/` and `EMAIL_OUTBOX_DIR` (default `./.outbox`) in `apps/worker/.outbox/` (gitignored).
- **`.outbox/` is the dev mailbox:** whenever `POSTMARK_SERVER_TOKEN` is unset, every email is a `.json` + `.html` pair there — open the newest `.html` to see what a client would receive. With the Postmark test-server token set, the worker and `deliver-once dispatch` are safe to run against the `@example.com` `cs_dev` contacts (accepted, never delivered).
- **PDFs block every network request except the agency's own `https` logo URL:** the Playwright brief/report render disables JavaScript and blocks all other requests, so a second external asset in a template silently fails to render (no error).
- **Delivery jobs idle** until `APP_URL` and `LINK_SIGNING_SECRET` are both set (start-up warning names the missing ones) — details in `packages/engine/CLAUDE.md`.
- **`WEB_MONITORING_ENABLED`** must be exactly `'true'` to enqueue `discover-pages`/accept manual pages; unset = `false`. Keep it unset until `https://rivalmonday.app/bot` exists. Accepting/dismissing a suggestion still starts paid vendor collection (`gbp`/`reviews`/ads) either way — only web crawling is gated.
- **`KB_IMPORT_ENABLED`** must be exactly `'true'` for `kb-import` / `kb-sync` (off: import returns `{ error: 'disabled' }`, sync no-ops). Both fetch only through `deps.politeRenderer()` (robots, shared limiter). A job handler's returned object becomes the pg-boss `output` (single-job batches); the web reads it via `JobStatusLookup`.
- **pg-boss needs a queue to exist before `send`:** register every job (with its queue policy/retry options) in `registerJobs` at startup and enqueue through `enqueue(boss, job, …)`; an ad-hoc option-less `createQueue` makes the first creator's options win.
- **Docker image** (`apps/worker/Dockerfile`, Railway): `CMD ["node", "--import", "tsx", "src/main.ts"]` so node is PID 1 and gets SIGTERM for the drain. `/healthz` on `PORT` (default 8080) is healthy iff <= 660 s since `max(start, last heartbeat)` and the cs_web queue grants did not fail (start-up, retried every heartbeat; body `queueGrants`); with `NODE_ENV=production` the worker exits 1 naming missing `REQUIRED_PROD_ENV` (`src/env.ts`). Deploy steps in `docs/DEPLOY.md`.
- **Logging and errors:** use `workerLog` (`log.ts`, pino JSON, never `console.*` outside `cli/**`) and wrap job handlers in `runJob` (`sentry.ts`: captures with job tags only on the last attempt (`retryCount >= retryLimit`), earlier attempts warn; cron `withMonitor` only for scheduled runs, marked by the raw `{ _cron: true }` payload `registerJobs` schedules). Call `ensureQueueGrants` (`queue-grants.ts`) right after `boss.start()` so `cs_web` can enqueue.
- **Sentry is inert without a DSN** (web and worker). `log.error(msg)` or `log.error({ ...fields }, msg)`, never `(msg, x)`; `apps/web/src/no-console.test.ts` guards `console.*`.
- **Spend pause and `usesAi` jobs (7b1):** job definitions that reach the model set `usesAi: true`; while the platform is paused `boss.ts` re-sends them with `startAfter: 600` (same `singletonKey`) and completes `{ deferred: 'ai_paused' }`. Cron jobs are not re-sent (a standard queue does not dedupe on `singletonKey`); the next tick retries. A client pause surfaces as `AiPausedError('client')` and `runJob` completes `{ skipped: 'spend_paused' }`, never a Sentry capture or retry. The daemon builds `createWorkerDeps(env)` with the shared guard; the `*-once` CLIs pass `{ aiGuard: false }` and run unguarded. `spend-guard` is hourly (`'7 * * * *'`, `short`, `retryLimit: 1`).
- **N pollers per queue share one handler and one `deps` (7c2):** `registerJobs` calls `boss.work` `localConcurrency` times with the *same* handler, so handlers run concurrently in one process. No per-job module-level state (counters, caches keyed by job); lazy singletons in `deps.ts` must stay synchronous `??=` or cached promises. Concurrency table `concurrency.ts`; `WORKER_QUEUE_CONCURRENCY=<queue>=<1-8>,…` (bad entry/unknown queue/out of 1-8 = exit 1 before `boss.start()`). The job list is built in `job-list.ts` (`createJobList`) *before* deps exist: `main.ts` passes a late-bound deps Proxy that throws if touched early, so factories may only use deps inside handlers/closures. Add a queue to `QUEUE_CONCURRENCY` only if its handler tolerates parallel runs; `concurrency.test.ts` checks every key is a registered job.
- **Pooled app URL means `prepare: false` (7c2):** `SERVICE_DATABASE_POOLED_URL` (Neon pooler, `app_service`) feeds the app `getDb()` with `{ max: appPoolMax, prepare: false }` (transaction pooling breaks prepared statements; no session state may be used). pg-boss and `cs_worker` stay on the direct `DATABASE_URL`. Required in production (`REQUIRED_PROD_ENV`, exit 1); unset (dev) = direct `SERVICE_DATABASE_URL`, prepared, pool still sized from the concurrency table (CLIs: `max` 5, either URL).
- **Vendor limiter and timeouts (7c2):** every vendor/AI HTTP call goes through the shared `createVendorLimiter` (`@cs/core/server` `token-bucket.ts`, limits `DEFAULT_VENDOR_LIMITS`); a request's `timeoutMs` is its time *after the slot is granted* (queueing never eats it), so pass `timeoutMs` in `init`, never `AbortSignal.timeout`, in a limited fetch. `*-once` CLIs are unlimited by design.
- **Captures defer, they do not sleep (7c2):** `web-capture-page` runs 4 pollers, the queue policy is `short`, and each send carries `singletonKey: 'capture:<id>'` (always, via `enqueueCapture`). `renderOrDefer` returns `deferred` when the host lock is held or the next slot is > 10 s away; the job re-enqueues itself with `startAfter` and the same key and returns `{ deferred: true }`. The host limiter remembers the largest Crawl-delay seen per host (never lowers until restart).
- **Rehearsal switches are refused in production (7c2):** `AI_PROVIDER_MODE`, `REHEARSAL_LIVE_CLIENT_IDS`, `VENDOR_FAKE_MODE`, `CRAWL_HOST_ALLOWLIST` (`REHEARSAL_ENV`, `rehearsalEnvErrors` in `env.ts`) work only with `SENTRY_ENVIRONMENT=staging` or `NODE_ENV` set and ≠ `production`; `main.ts` exits 1 and `createWorkerDeps` throws otherwise. **An unset `NODE_ENV` with any of them in `.env` makes `collect-once` and the other CLIs throw** (fail closed): unset them or set `NODE_ENV=development`. Staging crawling needs a non-empty allowlist (`allowlistedAssert` in `@cs/collectors` `net/guard.ts` composes with the SSRF guard; unlisted CDN sub-resources are aborted, expected). `fixture-hosts` (`src/cli/fixture-hosts.ts`) follows the same gate.
- **Readiness job (7c2):** `brief-readiness` (`25 * * * *`) writes `ops_alert` rows and emails platform staff; heartbeat output carries `{ queueGrants, rssMb, dbConnections, dbMaxConnections }` (the rehearsal report reads it). Meaning and handling: `docs/OPS.md` § Ops alerts.
