# @cs/site — working notes
The rivalmonday.com marketing site: a separate Next.js 16 deployable (port 3001 in dev). Static pages only; it talks to the app over public HTTP (`/api/waitlist`, `/api/site-status`).

## Boundary (gated)
- **Only `@cs/ui` (and `@cs/ui/styles.css`) may be imported from the workspace**, no other `@cs/ui/*` subpath: export a new shared helper from the `@cs/ui` root instead (as `brand-mark.ts` is). Never `@cs/db`, `@cs/tools`, `@cs/email` root or any server package; no `'server-only'`. `src/import-boundary.test.ts` (`pnpm --filter @cs/site lint`) checks `package.json` and every specifier; `pnpm --filter @cs/site check:bundle` checks `.next` output and traces after a build.
- **No secrets.** Read env only through `src/lib/env.ts` (`siteEnv`), with literal `process.env.NEXT_PUBLIC_*` reads (Next inlines only literals). Allowed: `NEXT_PUBLIC_*`, `VERCEL_ENV`, `NODE_ENV`; `SENTRY_AUTH_TOKEN|ORG|PROJECT` only in `next.config.ts`. No `.env` loading anywhere. A new `NEXT_PUBLIC_*` var is already hashed by turbo (`@cs/site#build` `env`).

## Cross-package test
- `packages/tools/src/waitlist/site-contract.test.ts` imports `apps/site/src/lib/waitlist-body.ts` to prove the form agrees with the server schema. After changing `waitlist-body.ts`, run `pnpm --filter @cs/tools exec vitest run site-contract`: turbo's affected filter won't pick `@cs/tools` up from a site change.

## Styling
- Design system v1 with marketing latitude (spec § 7.8): `@cs/ui` tokens and primitives, compose in `src/components/`; never edit `@cs/ui`.
- Site-local tokens live only in `src/app/site.css` (`text-display`, `text-display-sub`, `text-section`, `text-numeral`, `text-price`, `shadow-float`, `shadow-glow`, `shadow-frame`, `rounded-card`, `rounded-frame`, `--ring-change`/`.ring-change`, `.night-map`, `.night-veil`, `.night-veil-even`, `.site-container`). No hex, `rounded-[…]`, `text-[…px]` or shadow literals in components; `bash scripts/design-lint.sh` covers `apps/site/src`.
- **`cn()` from `@cs/ui` doesn't know the site keys:** tailwind-merge reads `text-display`/`text-display-sub`/`text-section`/`text-numeral`/`text-price` as a text colour (dropped next to `text-ink`) and `shadow-float` as a shadow colour. Keep site-key classes out of `cn()` merges with a colour/shadow class (plain `className` strings), since `@cs/ui`'s `lib/cn.ts` can't change here.
- Orange (`amber`) only for Friday, the Pilot pill and the owner canvas's uses (spec D14: hero underline, numbered markers, `Recommended:` callouts in `amber-text`). Each `bg-amber` file needs an `ALLOW_AMBER` entry with a reason in `design-lint.sh`.
- D14 component styling lives in `site.css`: `shadow-glow`/`shadow-frame`, `rounded-card` (14 px)/`rounded-frame` (20 px), `.btn-ink-ghost`, `.radar` (positions the hero's still rings; `components/motion/radar-rings.tsx` also draws rings elsewhere), `.scan-*` (every site picture goes through `components/media/scan-frame.tsx`: mat + range rings + scan tag; `tag` and `screenshot` come from content), and unlayered `.product-frame`/`.frame-chrome`/`.seg-tabs` (they restyle `@cs/ui` `Frame`/`TabsList`, whose `cn()` can't drop the defaults). Ink primary CTAs use `JOIN_INK_CLASS` (`join/join-button.tsx`).
- **No idle motion:** nothing loops or moves on scroll. Only short one-shot entrances exist: `reveal-quick` (a moved card, on mount), `sheet-in-*`, and the hero gallery's `gallery-fade` during its single round, after which it rests (and never moves under reduced motion). `src/no-idle-motion.test.ts` walks `src` and fails on any removed motion helper, class or keyframe name (add new names there); e2e "nothing on the home pages moves by itself" (after the round, on `/`, `/agencies`, `/business`) checks `document.getAnimations()` and the content, "the gallery plays once and then rests" and "with reduced motion the gallery never moves" drive it with `page.clock`.
- **Sides (Plan B):** `/` is the chooser, `/agencies` and `/business` are the two sides, `/pricing` is a 308 to `/agencies/pricing` (query kept). `src/lib/side.ts` (`sideOf`, `switchHref`) derives the side from the pathname, never from storage; `SideProvider` (layout) holds the server-built path lists. `useSide()` throws outside it; `useSideOrHome()` is only for the join provider/button and mobile CTA (the popup also mounts alone). The audience switch is the site's only `next/link` (besides the 404 page): a side change keeps the page loaded, so header, menu and popup follow the address; every other header, menu and footer link is a plain `<a>`.
- **Pricing rule:** no agency plan number on the business side (page, `<head>`, JSON-LD, popup); `/agencies/pricing` shows no business card; prices come only from `content/pricing.ts` `PRICING`. e2e "the business side's source has no agency plan number" scans the raw HTML for every `PRICING.agency` amount. The rule covers what a reader or a crawler is shown (visible text, `<head>`, JSON-LD, the popup); script files may carry agency strings (`join/copy.ts` is on every page).
- **Header below 1280 px (fallback):** the inline menu is `hidden xl:flex` and the Menu button `xl:hidden`, so the sheet holds the menu from 1024 to 1279 px; the bar keeps the switch, Sign in and the join button on one line (e2e "the header fits at 1024 px on both sides"; the agency bar has ~80 px to spare at 1280).
- **`HomeSectionShell` owns section padding** (`py-14 lg:py-18`; `pad={false}` opts out): a home section sets no vertical padding of its own.

## Build
- Pages must prerender (no `cookies()`/`headers()`/dynamic APIs in pages); no `output: 'export'` because security headers need the Next runtime.
- `next build` and `next dev` share `.next`: don't build while dev runs.

## Pages and content (17c)
- **Client boundary:** no `'use client'` module may import (even transitively) `content/pages`, `content/compare`, `content/integrations` or `content/sources`: they hold every rival, on or off. The layout builds nav/footer links server-side (`components/shell/nav-items.ts`: `navMenus()` = `{agency, business}` lists of `{label, href}`, `sidePaths()`) and passes them down as plain props (import-boundary test; `check:bundle` fails on a disabled rival's name in `.next/static`).
- Website-monitoring copy follows one constant, `content/website-monitoring.ts` `WEBSITE_MONITORING_LIVE`; the owner flips it after `WEB_MONITORING_ENABLED=true`.
- `content/pages.ts` is the registry: nav, footer, sitemap and collection pages (`/integrations`, `/sources`, `/compare`) are derived from it; never hand-edit them elsewhere. Enabled rivals = the known-rival array filtered by `siteEnv.comparePages` (`NEXT_PUBLIC_COMPARE_PAGES`, read at build; unset = no named compare pages). Never index an object by an env slug.
- Switching compare pages: `docs/DEPLOY.md` § Compare pages on/off. `pnpm --filter @cs/site check:facts` fails when an enabled rival's facts are over 90 days old; `deploy-site` runs `check:facts --all` (all five, on or off). CI's `site` job sets the same `NEXT_PUBLIC_COMPARE_PAGES` as Playwright `SERVER_ENV` so `E2E_SKIP_BUILD=1` reuses the build; change both together.
- Every claim about Rival Monday carries `verifiedIn` paths to shipped code (tests check they exist and match the ledger `docs/research/2026-10-29-phase-17c-claim-check.md`).
- Never name data vendors (DataForSEO, Apify, ScrapeCreators, Stadia): three scans guard it (compare, integrations, sources tests).
- OG colour hex lives only in `src/lib/og-theme.ts`; each `pageMetadata` page needs its own `opengraph-image.tsx`. The radar mark/tile reach Satori (`lib/og.tsx`: icons, OG cards) as a base64 SVG data-URI `<img>` from `@cs/ui` `radarMarkSvg`/`radarTileSvg`; a multi-child element needs `display: flex`.
- `verifiedIn` code paths live in `content/*-evidence.ts`, never in the content modules (keeps repo paths out of page bundles).
- The app's `/api/waitlist` fails closed (`400 check`) in env `dev` without a Turnstile secret — local end-to-end tries need Cloudflare's test keys in `.env`.
- Windows working copies can drift to CRLF while the index stays LF (`git ls-files --eol` shows `w/crlf`, status clean): `rm <file> && git checkout -- <file>`; a plain checkout doesn't rewrite.
- `/roadmap` (`content/roadmap.ts`) is **planned** work, never a claim: no `verifiedIn`, no ledger row; keep the "Planned · may change" status and notice (roadmap test). When a roadmap item ships, move its wording to claims-backed pages and drop it here, along with the home page's teaser (`COMMERCIAL.roadmapLine` in `content/home.ts`; no page shows the `RECOMMENDATIONS_ROADMAP` block now: `RecommendationsSection` renders it only with `roadmap` on, and `/agencies` turns it off).
- Dev from a worktree while the main checkout's site holds port 3001: `npx next dev -p 3011` in `apps/site` (stop it by killing the listener on 3011: TaskStop can leave the Next child running). `next dev` rewrites `next-env.d.ts`: never commit that change.
- The test-DB PreToolUse hook also counts other sessions' Playwright/headless Chrome processes and blocks site test runs (DB-free) while they live; the `RM_HOOK_OVERRIDE=1` escape is refused in auto mode, so wait for them or ask the owner. Your own `next dev`/`next start` in the same worktree trips it too (its Turbopack worker counts): stop the port listener before `vitest`/`e2e`.
- The sample's map rankings are hand-tuned (centre-out story): `export:sample-brief` overwrites them, then `rank-story.test.ts` fails. Re-run `node scripts/sample-rank-story.mjs content/sample-brief.json write`. Sample images (map, ad creatives, snapshot page images) are generated once and committed in `public/sample/`; never generate at runtime.
- **SEO pages:** `/for/*` (`content/industries.ts`) and `/guides/*` (`content/guides.ts`) are registry collections (`group` `industries`/`guides`), linked from the footer, sitemap, `llms.txt` and in-text links only, never the top nav (`industries-guides.test.ts`). Their product statements use ledger wording only; website lines go through `websitesLine()` (`WEBSITE_MONITORING_LIVE`). Guides carry `published`/`updated` (Article JSON-LD): bump `updated` on a real edit, and an `image` from committed `public/sample` files, with a `caption` when it shows sample or fictional content. - **Inter ships in the repo** (`src/app/fonts/inter-latin-wght-normal.woff2`, one variable file via `next/font/local`; same in `apps/web`). Don't go back to `next/font/google`: it fetches at build time and broke CI builds. A new file under `apps/web/src/app/` needs a rule in `apps/web/scripts/e2e-affected-rules.ts` (coverage guard). - **Tests:** vitest only picks up `src/**/*.test.{ts,tsx}`, `content/**/*.test.ts` and `scripts/**/*.test.ts`; a test beside `next.config.ts` never runs (keep config values in `src/lib`, like `headers.ts`). There is no root `e2e:affected` script: the site's E2E is `pnpm --filter @cs/site e2e`.

VERCEL_ENV= pnpm exec next build`), `pnpm exec next start -p 3011`, then `pnpm --filter @cs/site capture:gallery` (`--path /agencies` default; Git Bash needs `MSYS_NO_PATHCONV=1` for a `/` path), then kill the listener on 3011 and `git checkout -- next-env.d.ts`.
