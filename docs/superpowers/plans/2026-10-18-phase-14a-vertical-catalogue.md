# Phase 14a — Vertical catalogue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Lean plan format (root `CLAUDE.md`): interfaces are binding; full code only for SQL/RLS, security logic, non-obvious algorithms and decided copy.

**Goal:** Verticals and business areas live in Postgres as a growing global catalogue. Setup auto-drafts a missing vertical from the Google profile (AI, quoted), agencies add missing business areas, and operators review and merge in `/platform/verticals`.

**Architecture:** New global tables (`vertical`, `business_area`, `vertical_category`, `vertical_draft`) are readable only by the service role. `@cs/verticals` assembles them back into today's `VerticalPack`, so engine consumers keep the `PackLoader` interface and only the loader source changes. HVAC/dental are seeded with the same ids and versions. A `generic` pack supplies the numeric knobs of new verticals.

**Tech Stack:** TypeScript, Drizzle + custom SQL migrations, zod, `@cs/tools` `defineTool`, pg-boss worker, Next.js App Router + shadcn/ui, OpenRouter via `@cs/ai`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-phase-14-dynamic-verticals-runbooks-design.md` (§1 D1–D7, D13; §2). Brief: `docs/work/phase-14b.md`.

## Global Constraints
- Node 24, pnpm 10, Turborepo strict env. A new env var needs `turbo.json` `globalPassThroughEnv` (none planned).
- The repo is LF only. Never edit applied migrations; create new ones with `pnpm --filter @cs/db generate --custom --name=<x>`, numbered from the **next free number at execution time**.
- Model input goes through `redactForModel`, never bare `redactContactInfo`. *No evidence, no claim*: every AI-drafted item carries a quote that is a substring of the source text.
- Web reads are registered tools; web writes go through `runTool`. Page refusals → 404.
- Catalogue names never contain client data (D3). Platform text never names Rival Monday.
- Client lists and schedulers filter `client.status = 'active'`. Event readers filter `retracted_at IS NULL`.
- History is never rescored. Catalogue changes reach new runs only, with no backfill (D13).
- Tests: focused tests via `pnpm --filter <pkg> exec vitest run <pattern>`; reviewers run `pnpm test:affected` (+ `pnpm --filter @cs/web e2e:affected` when web changes). Test DB is `cs_phase_14b_test` on the local cluster.

## Decisions (plan-local; do not re-open)
- **P1 Catalogue access:** the tables are service-only (RLS forced, no policy, all `app_user` privileges revoked), following the `theme_proposal` pattern. Agencies read them through tools. This supersedes the spec §2.1 line "every agency/web role can select".
- **P2 Drafting is synchronous:** `draft_vertical` is a web tool (one AI call, ≤ 30 s), not a worker job, because no client exists at the lookup step. Drafts are cached per place in `vertical_draft`. Cap: 10 drafts per agency per day. This replaces spec §2.3 step 4's "`vertical-draft` job".
- **P3 No lead storage change:** a pool/intake lead whose category matches nothing is accepted through the same "new business type" panel in the lead card. This replaces spec §2.3 step 8.
- **P4 `SetupLookup` is unchanged:** `find_business` keeps `suggestedVerticalId`, and the spec's `verticalMatch` is that field. The draft fetches the GBP profile itself.
- **P5 `generic`:** a third YAML pack `packs/generic.yaml`, seeded as vertical row `generic`, never listed or selectable. A new vertical's `config` holds only its text parts; numeric knobs, playbooks and self-rules come from `generic` via deep merge (objects merged, arrays replaced).
- **P6 Cost per vertical (D7):** `llm_call.vertical_id text null` and `CallScope.verticalId?: string`. Per-vertical tagging/review calls and `vertical_draft` set it. `/platform/costs` gains an "AI by business type (30 days)" table read from `llm_call`.
- **P7 Cache:** one catalogue instance per process with a 60 s TTL (worker, web, MCP). Write tools call `invalidate()` on their own instance. This simplifies spec §2.2's "worker jobs load once per run".
- **P8 Merge of derived data:**
  - `review_analysis` and `price_block_map` rows of the merged side are deleted (regenerated by later runs only for new input, per D13).
  - `price_point`, `event.services` (table `event`), `playbook_override`, `agency_profile.verticals`, `client.*` are re-keyed.
  - Decided `theme_proposal` rows stay (history); `proposed` ones for the source vertical are deleted.

## Review Focus

```ts
export type CatalogStatus = 'reviewed' | 'unreviewed' | 'merged';
export interface VerticalRow { id: string; name: string; status: CatalogStatus; mergedInto: string | null;
  version: number; gbpCategories: string[]; gbpRelatedCategories: string[]; config: Record<string, unknown>;
  draftEvidence: unknown | null; createdByAgencyId: string | null; }
export interface BusinessAreaRow { verticalId: string; id: string; name: string; aliases: string[];
  status: CatalogStatus; mergedInto: string | null; evidence: unknown | null; createdByAgencyId: string | null; }
export const GENERIC_VERTICAL_ID = 'generic';
/** generic.config ⊕ row.config (deep merge: objects merged, arrays replaced) + id/name/version from row,
 *  services from non-merged areas (sorted by name), discovery.categories/related from row. Validated with verticalPackSchema. */
export function assemblePack(row: VerticalRow, areas: BusinessAreaRow[], generic: VerticalRow): VerticalPack;
/** Inverse for seeding: config = pack minus id/name/version/services/discovery.categories/related_categories. */
export function splitPack(pack: VerticalPack): { row: Omit<VerticalRow,'status'|'mergedInto'|'draftEvidence'|'createdByAgencyId'>; areas: Pick<BusinessAreaRow,'id'|'name'|'aliases'>[] };
export interface VerticalSummary { id: string; name: string; status: CatalogStatus; services: { id: string; name: string }[] }
export interface Catalog { packs: PackLoader; list(): Promise<VerticalSummary[]>; resolveId(id: string): Promise<string | null>; invalidate(): void }
export type PackLoader = (verticalId: string) => Promise<VerticalPack>;   // same shape as engine's
export function createCatalog(source: () => Promise<{ verticals: VerticalRow[]; areas: BusinessAreaRow[] }>, opts?: { ttlMs?: number; now?: () => number }): Catalog;
```
**Behaviour:**
- `packs(id)` follows `mergedInto` chains (max depth 5) and throws `Error('Unknown vertical: <id>')` for an unknown id or `generic`.
- `list()` excludes `generic` and `merged` rows, sorted by name.
- `resolveId` returns the final non-merged id, or null.
- A row whose assembly fails validation is logged once (`console.warn`) and treated as unknown. It never throws inside `list()`.
- TTL default 60 s. One in-flight fetch is shared, and a failed fetch is not cached.
- `generic.yaml`: start from `hvac_plumbing.yaml` with the same numeric values; `audience_noun: customers`; one placeholder area `general` "General service"; `themes` = the HVAC themes that are vertical-neutral (price, wait time, communication, staff, quality — implementer picks ids from HVAC). Playbook titles/templates rewritten without HVAC nouns (no "AC", "furnace", "plumbing", "homeowners"). **Copy sign-off:** list every rewritten string in the work file under "Copy for owner sign-off".
**Follow pattern:** `loader.ts` (validation errors with `source`), `createPackLoader` in `engine/src/tag/tag-stage.ts`.

**Tests (TDD):**
- `assemblePack(splitPack(yaml))` deep-equals the YAML pack for `hvac_plumbing`, `dental`, `generic` (golden).
- A text-only config merges with generic: `type_weights` come from generic, `audience_noun` from the row.
- A merged chain resolves; `packs('generic')` throws; an invalid row is skipped by `list()` and `packs` throws "Unknown vertical".
- TTL: a second call within the TTL does not refetch; after `invalidate()` it does; a failed fetch retries.

```ts
// similar.ts
export function normaliseName(s: string): string;   // NFKC, lowercase, strip punctuation, drop GENERIC_WORDS, singularise trailing 's'/'ies'
export const GENERIC_WORDS: readonly string[];       // ['craft','service','services','shop','store','company','co','and','the','local']
export function similarVerticals(name: string, catalogue: { id: string; name: string; categories: string[] }[], max?: number): { id: string; name: string }[];
//  match if normalised equal, OR token-set Jaccard ≥ 0.5, OR normalised Levenshtein distance / max(len) ≤ 0.25; sorted by score; max default 3
// tools
list_verticals   { } → { verticals: VerticalSummary[] }                     permission 'read', channels ['web','mcp']
create_vertical  { name: string 2-60; areas: {name: string 2-80; aliases?: string[]≤8}[] 1-20; audienceNoun?: string≤40;
                   seedKeywords?: string[]≤5; categories: string[] 1-10; relatedCategories?: string[]≤10;
                   themes?: {name: string; description?: string}[]≤12; draftPlaceId?: string≤300 }
                 → { verticalId: string; droppedCategories: string[] }     permission 'manage', agency_admin|account_manager
add_business_area { verticalId; name: 2-80; aliases?: string[]≤8 } → { verticalId; areaId }   permission 'manage'
update_vertical  { verticalId; name?; audienceNoun?; seedKeywords?; categories?; relatedCategories?; themes?;
                   areas?: {id?: string; name; aliases?}[] } → { verticalId; version }   creator agency while unreviewed (else permission_denied → 404)
```
**Behaviour:**
- Slug = `normaliseName`-based snake case, max 40, prefixed `v_` if it starts with a digit. On a slug collision with a different vertical, append `_2`, `_3`.
- **Idempotent create:** if a non-merged vertical with the same slug exists, is `unreviewed` and was created by the same agency, return it (Review Focus 4). **Merge algorithm (binding, one transaction, `SELECT ... FOR UPDATE` on both vertical rows):**
```sql
-- vertical merge src -> tgt, after validating: src <> tgt, both non-merged, neither 'generic',
-- every src area id is a key of areaMap; mapped targets exist in tgt; 'move' ids don't collide in tgt.
-- 1. areas
UPDATE business_area SET vertical_id = :tgt WHERE vertical_id = :src AND id = ANY(:moveIds);        -- moved (keep status)
UPDATE business_area SET status = 'merged', merged_into = m.tgt_area                                -- mapped
  FROM unnest(:srcAreaIds::text[], :tgtAreaIds::text[]) AS m(src_area, tgt_area)
  WHERE vertical_id = :src AND id = m.src_area;
-- 2. clients (service ids remapped, de-duplicated, order kept)
UPDATE client c SET vertical_id = :tgt, services = (
  SELECT coalesce(jsonb_agg(s ORDER BY ord), '[]'::jsonb) FROM (
    SELECT DISTINCT ON (s) s, ord FROM (
      SELECT coalesce(:areaMapJson::jsonb ->> e, e) AS s, ord
      FROM jsonb_array_elements_text(c.services) WITH ORDINALITY AS t(e, ord)) x
    ORDER BY s, ord) y)
  WHERE c.vertical_id = :src;
-- 3. event.services {verticalId: serviceId|null}  (Drizzle `changeEvent`; the table is named `event`)
UPDATE event SET services = (services - :src) || jsonb_build_object(:tgt,
    CASE WHEN services->>:src IS NULL THEN 'null'::jsonb
         ELSE to_jsonb(coalesce(:areaMapJson::jsonb ->> (services->>:src), services->>:src)) END)
  WHERE services ? :src AND NOT services ? :tgt;
UPDATE event SET services = services - :src WHERE services ? :src;
-- 4. price_point: drop open duplicates, then re-key
DELETE FROM price_point p WHERE p.vertical_id = :src AND p.ended_at IS NULL AND EXISTS (
  SELECT 1 FROM price_point q WHERE q.vertical_id = :tgt AND q.ended_at IS NULL AND q.tracked_page_id = p.tracked_page_id
    AND q.service_id IS NOT DISTINCT FROM coalesce(:areaMapJson::jsonb ->> p.service_id, p.service_id)
    AND q.unit IS NOT DISTINCT FROM p.unit AND q.qualifier IS NOT DISTINCT FROM p.qualifier AND q.amount = p.amount);
UPDATE price_point SET vertical_id = :tgt, service_id = coalesce(:areaMapJson::jsonb ->> service_id, service_id) WHERE vertical_id = :src;
-- 5. derived analyses dropped (P8)
DELETE FROM review_analysis WHERE vertical_id = :src;
DELETE FROM price_block_map WHERE vertical_id = :src;
DELETE FROM theme_proposal WHERE vertical_id = :src AND status = 'proposed';
-- 6. agency settings
DELETE FROM playbook_override o WHERE o.vertical_id = :src AND EXISTS (
  SELECT 1 FROM playbook_override t WHERE t.agency_id = o.agency_id AND t.vertical_id = :tgt AND t.playbook_id = o.playbook_id);
UPDATE playbook_override SET vertical_id = :tgt WHERE vertical_id = :src;
UPDATE agency_profile SET verticals = ARRAY(SELECT DISTINCT unnest(array_replace(verticals, :src, :tgt))) WHERE :src = ANY(verticals);
-- 7. categories + rows (also append src's gbp_categories + gbp_related_categories to tgt.gbp_related_categories, distinct; pre-flight ruling)
UPDATE vertical_category SET vertical_id = :tgt, kind = 'related' WHERE vertical_id = :src;
UPDATE vertical SET status = 'merged', merged_into = :tgt, updated_at = now() WHERE id = :src;
UPDATE vertical SET version = version + 1, updated_at = now() WHERE id = :tgt;
```
