## Phase 3a carry-over (live verification, 2026-10-01)
- ✅ **Stage versioning is one-directional — closed in Phase 3d:** a stage run under a newer version now supersedes the same subject's `detected_change` rows from older versions (`status: 'superseded'`); each affected event loses that evidence link and is retracted (`reason: 'superseded'`) once no live evidence remains. A tag-stage version bump still does not re-tag already-tagged changes — recorded as a known limitation (decision 7).
- ✅ **Volatile masks never expire, no AM unmask path — closed in Phase 3d:** a mask expires when its block hasn't changed across the full learning window (or no longer exists); `unmaskBlock()` lets an AM unmask by hand and that block is never auto-masked again (`volatile_block.unmasked_at`). The AM-facing UI for this is still Phase 5.
- ✅ **`decision_review` has no resolution flow — closed in Phase 3d:** `resolveDecisionReview()` validates the AM's answers, merges them over the model's, detaches/retracts/re-scores as needed, and records them as labels on the linked sample; the `decisions` CLI (`reviews`/`resolve`) is the interface until the Phase 5 AM UI exists.
- ✅ **Events scored only for clients linked within `SCORE_WINDOW_DAYS` — closed in Phase 3d:** the score sweep also offers an event outside that window when the client's link is younger than `SCORE_WINDOW_DAYS` and the event occurred within `LATE_LINK_LOOKBACK_DAYS` (90); the `alert_max_age_days` cap still stops a late-offered old event from paging anyone.
- ✅ **`EXTRACTOR_VERSION` bumps don't refresh stored blocks — closed in Phase 3d:** `ensureBlocks` under a new `EXTRACTOR_VERSION` deletes the capture's old `capture_block` rows before inserting the new ones; `EXTRACTOR_VERSION` bumped to 2 for the camelCase consent-token fix (below); volatile learning now only reads captures extracted under the current version.
- ✅ **`extractZips` false positives/misses — closed in Phase 3d:** a 5-digit number now counts as a ZIP only after a state/ZIP-label context or inside a list of ≥ 2 such numbers, never next to a unit/`$`/phone/decimal; ZIP+4 and sentence-final ZIPs are read. Two residuals carried below (`'TX 36000 BTU'` state-before-capacity misread; a list of two unrelated counts joined by "and"/comma still misreads as ZIPs — decision 17's list rule needs that case to work for real ZIP lists).
- ✅ **Per-client `scoreThresholds` not validated — closed in Phase 3d:** the DB rejects malformed `client.score_thresholds` (CHECK: numbers, 0 ≤ brief < alert ≤ 100); `scoreForClient` also falls back to the pack's routing with a warning if a row somehow holds bad values.
- ✅ **Score sweep has no backoff — closed in Phase 3d:** a failed (event, client) score writes `score_failure` (attempts, error); the sweep and `scoreEvent` skip a pair until `RETRY_BACKOFF_MINUTES × 2^(attempts−1)` has passed and give up after `MAX_STAGE_ATTEMPTS`; success deletes the row.
- ✅ **`engine-once` argument validation and exit code — closed in Phase 3b:** `--competitor`/`--rounds`/`--moves` are now shape/range-checked with clear CLI errors, and the CLI exits non-zero when `errors > 0` (previously always exit 0).
- ✅ **Volatile learning based on positional block keys — closed in Phase 3d:** consecutive captures are aligned with `alignBlocks`; a block keeps its identity across captures through unchanged/modified alignments, so an insertion at the top no longer makes every following block look volatile. One residual: `alignBlocks`' own same-key pairing step can give a volatile block's identity to an inserted sibling when its text also changes in the same capture — carried below.
- ✅ **PII beyond contact details — closed in Phase 3c:** `redactForModel` wraps `redactContactInfo` with `compromise` NER person-name redaction and a fixed serious-health-condition list, applied at every embed/decide/chat call site (replacing bare `redactContactInfo`).
- ✅ **Routing ignores event age — closed in Phase 3b:** `scoring.alert_max_age_days` (default 7, per vertical pack) caps an event's route to at most `brief` when it is older than that at scoring time — backlogs and newly linked clients can no longer page anyone for old events.
- ✅ **Sweep re-enqueues have no `singletonKey` dedupe — closed in Phase 3b:** engine queues use pg-boss's `short` policy with a per-subject `singletonKey`, so a subject still queued from the previous sweep is not enqueued twice.
- ✅ **`engine-once` exits 0 even when `errors > 0` — closed in Phase 3b** (see the `engine-once` validation item above).
- ✅ **The same price shown in two blocks of one capture yields two events — closed in Phase 3b:** the cross-channel merge (identical non-empty numeric facts merge without a model call; otherwise a Noul "same offer?" call at threshold 0.8) collapses it to one event with two evidence links; a genuinely different second price cut still stays a separate event.
- ✅ **Churn guard gaps — closed in Phase 3d:** churn (added + removed + same-key rewrites below `MOVE_SIMILARITY`) now runs before paid work — on a churned page only money changes are embedded/gated, everything else is stored as a `suppressed` detected change (flag `churn`, capped at 200) instead of being silently dropped or paid for per block. Residuals (pre-cap suppressed-count reporting, `CHURN_SUPPRESSED_MAX` untested, masked non-money blocks on a churned page going to `suppressed`) carried below.
- ✅ **Consent tokens in camelCase or compound vendor names — closed in Phase 3d:** the extractor's consent-banner filter now also matches camelCase/compound tokens (`cookieConsent`, `cookieBar`, `cmplz-cookiebanner`, `CookieLawInfo`), shipped under `EXTRACTOR_VERSION` 2 (which also triggers the re-extraction fix above).
