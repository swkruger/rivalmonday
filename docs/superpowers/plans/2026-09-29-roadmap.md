# Core Platform — Implementation Roadmap

**Spec:** [docs/superpowers/specs/2026-09-29-core-platform-design.md](../specs/2026-09-29-core-platform-design.md)

The core platform is delivered in **seven phases**. Each phase has its own detailed plan (written when the previous phase is merged, so it builds on real code), ends in working, tested software, and is small enough to review as one branch.

| Phase | Plan | Delivers | Spec sections | Est. |
|---|---|---|---|---|
| **1. Foundations** | [phase-1-foundations](2026-09-29-phase-1-foundations.md) | Monorepo, Postgres + RLS tenancy, access context, tool registry with audit, AI layer (OpenRouter, Jev, LLM decisions, confidence cascade, cost ledger), vertical packs, pg-boss worker, CI | §3, §7, §8.1, §10 | 2–3 wks |
| 2. Collection & evidence | *to be written* | R2 evidence vault, Playwright web collector (robots, UA, rate limits, hash-first), page discovery, DataForSEO (GBP, reviews, ads, jobs, geo-grid), Meta ads via Apify/ScrapeCreators, Instagram, competitor discovery, reviewer pseudonymisation, collection schedules, capture status | §4 | 3–4 wks |
| 3. Intelligence engine | *to be written* | Main-content extraction, volatile-region masking, embeddings + semantic diff, numeric rule layer, tagging via DecisionProvider, cross-channel merge, scoring & routing, moves rules, review themes & benchmark, price normalisation, Jev shadow evaluation, Anthropic-direct batch provider | §6, §7.3 | 3–4 wks |
| 4. Briefs, recommendations & alerts | *to be written* | Brief gather/select/write, deterministic + Jev verifier, quiet-week handling, recommendations & playbooks, alerts with throttling, Postmark email, signed deep links, PDF export, quarterly report | §8.5, §9 | 2–3 wks |

**Phase 0 (parallel with Phase 1):**
- **Validation:** GHL/Vendasta marketplace check, external agency LOIs, US counsel review (before Phase 7 pilot).
- ✅ **Branding (done 2026-09-30):** Rival Monday + assistant Friday, tokens and typography in [docs/brand/brand.md](../../brand/brand.md); five example pages in [docs/brand/mockups/](../../brand/mockups/) (client overview, changes & evidence, reviews & reputation, agency approval queue, white-label settings). Original scope: product name (needed before Phase 2's first crawl — used in the bot User-Agent), default AI assistant name (agencies can rename it), logo direction, colour tokens, typography. Output: `docs/brand/` + design tokens consumed by `packages/ui` in Phase 5.
- **Example pages:** high-fidelity mockups of the key screens in the agreed style (reference: card-based KPI overview, sidebar navigation, highlighted CTA panel, per-tier automation modes, white-label settings — see Paige by Merchynt screenshots). Output: static HTML mockups reviewed with the user and pilot agencies; they become the Phase 5 design reference.

**Phase dependencies:** 1 → 2 → 3 → 4; 5 can start after 1 (UI against seeded data) but its data modules land after 3; 6 needs 1 + 3 (tools read engine output); 7 last.
