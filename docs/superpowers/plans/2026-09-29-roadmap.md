## Phase 3a carry-over (live verification, 2026-10-01)
- **Stage versioning is one-directional:** bumping a stage's version (e.g. `WEB_DIFF_VERSION`, `TAG_VERSION`) makes the stage re-run, but does not retract or supersede outputs already written under an older version — old `detected_change`/`change_event`/`event_score` rows from a prior stage version stay in place alongside the new ones. No retraction/superseding mechanism exists yet.
- **Volatile masks never expire** and have no account-manager unmask path — `learnVolatileBlocks` only ever adds masks, never removes one once a block stops being noisy. Needs an unmask UI/flow — Phase 5.
- **`decision_review` has no resolution flow yet** — rows are written (per spec §6.1, for low-confidence meaningful dismissals) but nothing marks them resolved or surfaces them to a human reviewer. Needs a review queue UI — Phase 5.
- **Events are scored only for clients linked within `SCORE_WINDOW_DAYS`** of the event's `occurredAt` — a client linked to a competitor after that window closes never gets a score for events that already happened.
- **`EXTRACTOR_VERSION` bumps don't refresh stored blocks:** re-running block extraction with a newer `EXTRACTOR_VERSION` does not invalidate/re-extract existing `capture_block` rows written under an older version, and `learnVolatileBlocks` ignores `stage_version` entirely when deciding what counts as noisy — a changed extraction rule can silently mix old- and new-version blocks when learning volatility.
- **`extractZips` has false positives and misses real ZIPs:** it matches any bare 5-digit number (e.g. "36000 BTU" reads as ZIP `36000`), and misses ZIP+4 (`75001-1234`) and a ZIP at the very end of a sentence (no trailing word boundary case checked). Since the final-review fixes, `territory_overlap` applies only to `service_area_change` and `new_location` events (`TERRITORIAL_TYPES`), so a stray number can no longer archive a price cut; a wrong ZIP can still wrongly cut a territorial event to 0.3. ZIP-extraction accuracy remains carry-over.
- **Per-client `scoreThresholds` are not validated** — a vertical pack or client config with malformed/out-of-range thresholds is not caught at load time; it would only surface as silently-wrong scoring behavior.
- **The score sweep has no backoff** — unlike the diff/tag sweep stages (exponential backoff via `RETRY_BACKOFF_MINUTES × 2^(attempts-1)`), a failing score stage is retried on the same cadence with no growing delay.
- ✅ **`engine-once` argument validation and exit code — closed in Phase 3b:** `--competitor`/`--rounds`/`--moves` are now shape/range-checked with clear CLI errors, and the CLI exits non-zero when `errors > 0` (previously always exit 0).
- **Volatile learning is based on positional block keys and counts pending changes as insignificant:** an insertion at the top of a list shifts every following key (`li#0`, `li#1`, …), which can make the wrong blocks look volatile and mask them. Learning should be based on alignment results instead.
- **PII beyond contact details still reaches models:** `redactContactInfo` removes phones and emails only; patient names and procedures (e.g. dental testimonials) are sent as-is. Fold this into the Phase 3c NER pass.
- ✅ **Routing ignores event age — closed in Phase 3b:** `scoring.alert_max_age_days` (default 7, per vertical pack) caps an event's route to at most `brief` when it is older than that at scoring time — backlogs and newly linked clients can no longer page anyone for old events.
- ✅ **Sweep re-enqueues have no `singletonKey` dedupe — closed in Phase 3b:** engine queues use pg-boss's `short` policy with a per-subject `singletonKey`, so a subject still queued from the previous sweep is not enqueued twice.
- ✅ **`engine-once` exits 0 even when `errors > 0` — closed in Phase 3b** (see the `engine-once` validation item above).
- ✅ **The same price shown in two blocks of one capture yields two events — closed in Phase 3b:** the cross-channel merge (identical non-empty numeric facts merge without a model call; otherwise a Noul "same offer?" call at threshold 0.8) collapses it to one event with two evidence links; a genuinely different second price cut still stays a separate event.
- **Churn guard gaps:** it counts only added/removed blocks, so a full copy rewrite that keeps the DOM structure (all `modified`) still triggers a decide call per block; embeddings and `value_extract` are paid before the guard runs; and non-money changes dropped by the guard are not re-offered on the next diff.
- **Consent tokens in camelCase or compound vendor names** (`cookieConsent`, `cookieBar`, `cmplz-cookiebanner`, `CookieLawInfo`) are no longer stripped since the segment-based filter; they survive as stable blocks (noise, not false events). Add vendor ids or a camelCase split.

- Hiring-move summary text doesn't truncate long job labels; several `buildStructuredSummary` branches (`ad_stopped`, `new_location`, `rating_change`, `service_removed`) are untested; a missing-change lookup throws before `runStage` can record it; no offer question is asked when no client tracks the competitor (Task 10).

- The nightly moves job has no `stage_run` idempotency claim by design (it's a recurring job with idempotent upserts); a racing concurrent run for the same client fails on the `move_open_unique` constraint and is retried the next night — accepted risk, an occasional failed `moves-client` job (Task 14, controller ruling).
- `engine-once --moves` and its exit code are untested at the CLI level (the CLI has no unit tests) (Task 15).
- The pre-3b "no-retry queues" worker test is now a strict subset of the new `short`-policy test — candidate for consolidation (Task 15).
