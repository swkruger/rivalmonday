# app-style (canvas component styling in the app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the owner canvas's subtle component styling into the product app as opt-in `@cs/ui` variants (stage A), then adopt them on named pages, the recommendations board and Friday (stage B), with before/after screenshots and a dev-only gallery.
**Architecture:** Additive tokens in `packages/ui/src/styles.css`, new variants/props on existing primitives (defaults byte-identical), one new primitive (`NumberMarker`), a `PageHeader` `tone="ink"` band that re-scopes text tokens, design-system doc amendments, then per-page opt-in.
**Tech stack:** Tailwind v4 tokens, cva, Radix (Tabs/ToggleGroup), Next.js App Router, vitest + Testing Library, Playwright shots harness (`apps/web/e2e-shots`).
**Spec:** `docs/superpowers/specs/2026-11-04-app-style-design.md` (AS1–AS17, §§ 2–6). Brief: `docs/work/app-style.md`.

## Global constraints
- **AS2:** every existing default class string in `@cs/ui` stays byte-identical; a page changes only in the stage-B task that names it. No copy changes (AS17), no migration, never touch `apps/site`.
- Design system v1 binding: D-15 36 px controls; radii 4/6/8/12/full; weights 400/500/600; chart roles untouched; Friday pill untouched; text ≥ 4.5:1, UI ≥ 3:1.
- White-label: only `--primary`/`--secondary`(+derived) vary per agency (`themeVars`, hex-only values); agency primary only on the active segmented tab and existing selected states (AS4). Button labels on primary via `--primary-foreground` (`readableTextOn`).
- Tokens only: no hex, `text-[…px]`, `rounded-[…]` or shadow literals in `.tsx`; tokens and token-scoped CSS go in `packages/ui/src/styles.css`. A new custom theme key used via `cn()` goes into `packages/ui/src/lib/cn.ts`.
- `bash scripts/design-lint.sh` stays at total 0; each `ALLOW_*` entry has a `# reason` line.
- Tests assert intent (`data-variant`, `data-tone`, `data-slot`, roles, computed contrast), not class strings, except where a test pins a token value.
- Server components import only components from `'use client'` modules (`apps/web/CLAUDE.md`); shared class strings live in plain modules.
- Read `docs/gotchas-cross-cutting.md`, `packages/ui/CLAUDE.md`, `apps/web/CLAUDE.md` before coding. LF only. Commits end with the `Co-Authored-By` line from root CLAUDE.md (your own model).
- Test scope: focused tests per task (`pnpm --filter @cs/ui exec vitest run <pattern>`, `pnpm --filter @cs/web exec vitest run <pattern>`); `pnpm test:affected` and `pnpm --filter @cs/web e2e:affected` only in Task 13. One test run per DB; never alongside `shots` or `e2e`.
