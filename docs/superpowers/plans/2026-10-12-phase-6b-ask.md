# Phase 6b — Ask assistant "Friday": Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-client chat assistant ("Friday", renamable) that answers from registry tools on the `ask` channel. Answers are verified before display (citations + Noul support check), writes require a confirm click, there is a hidden per-client monthly question quota, model-written weekly starter questions, author-only threads, and a platform-admin review view with a per-client opt-out.

**Architecture:**
- `@cs/ai` gains OpenRouter tool calling.
- A new package `@cs/ask` owns the quota transaction (`beginTurn`), the turn loop (`runTurn`: guard → ≤ 8 tool steps → grounding → persist), citation parsing and starter generation.
- `apps/web` exposes one SSE route `POST /api/ask/turn`, confirm/save server actions, the Ask pages, settings fields and `/platform/ask`.
- The worker runs `ask-starters` after each client's brief job.

**Tech stack:** existing (Node 24, pnpm 10, Turborepo, Next 16.3.8, Better Auth 1.7.7, Drizzle 0.44, Zod 4, Vitest 3, Playwright 1.63). **No new dependencies.**

**Spec (binding):** [`docs/superpowers/specs/2026-10-12-phase-6b-ask-design.md`](../specs/2026-10-12-phase-6b-ask-design.md) (e1–e11, interfaces, decided copy). 6a spec d4/d5/d12/P15 where cited. Core spec §8.4 only where cited.

## Global constraints
- **Decided copy (verbatim, spec):**
  - quota: "You have reached this month's quota."
  - no evidence: "I don't have evidence for that in the monitored data."
  - refusal: "I can only help with your competitors and market."
  - error: "{assistantName} couldn't answer just now — please try again."
  - disclosure: "Conversations may be reviewed by {productName} to improve answers."
  - cancel: "Cancelled."
- **Clients never see usage or limits (e4):** no counts, quota numbers or "ask your account manager" anywhere a client role can reach (pages, tool outputs, SSE events, error text).
- **Thread privacy (e5):** RLS author-only; there is no agency-admin exception. Platform review reads through the service role, only where `client.ask_review_allowed`.
- **Model never executes writes (e8):** a call to `submit_feedback` / `update_recommendation_status` / `add_recommendation` from the model becomes a `proposed` action and ends the turn; code runs it on Confirm.
- **Limits:** ≤ 8 model tool steps, 90 s turn deadline, history = last 10 messages, question 1–2000 chars, title ≤ 80, evidence text ≤ 4,000 chars per id for grounding, starter questions exactly 4 × 10–90 chars.
- **Invariants:**
  - model input goes through `redactForModel` (tool outputs are already `forChannel`-redacted off-web, 6a d12);
  - `upsell_tag` never reaches client roles;
  - event readers filter `retracted_at IS NULL`;
  - schedulers filter `client.status = 'active'`;
  - page refusals → `notFound()`;
  - web writes go through `runTool`.
- **Repo:**
  - LF only.
  - Every commit ends `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (subagents may name their own model).
  - Never stage `.env`, `.claude/` (except `rm-*` skills), `App/`, `.superpowers/`.
  - Never edit applied migrations; generate with `pnpm --filter @cs/db generate --custom --name=<x>` for custom SQL.
- **Tests:**
  - Use the local test cluster (`bash scripts/local-test-db.sh start`) and this worktree's DB `cs_phase_6_test`. Never two runs on one DB.
  - Implementers: focused `pnpm --filter <pkg> exec vitest run <pattern>` in the foreground.
  - Reviewers: `pnpm test:affected --base <task BASE>` (background) and, for web tasks, `pnpm --filter @cs/web e2e:affected`.
  - Full suite and full E2E only in `/rm-merge`.
  - Unit and E2E tests never call OpenRouter.
- **Next.js:** read `apps/web/node_modules/next/dist/docs/` for route handlers/streaming before Task 8; `params`/`headers()`/`cookies()` are async.

## Decisions
Spec e1–e11 are binding. **Plan-local** (owner confirms with plan approval):
- **Q1** **New env var `ASK_FAKE_AI=1`** (needs owner OK). The web app builds Ask with a deterministic scripted AI (`createScriptedAskAi` from `@cs/ask/testing`) instead of OpenRouter. It is set only in `E2E_SERVER_ENV`. `parseWebEnv` throws if it is set together with `VERCEL_ENV=production`. Added to `turbo.json` `globalPassThroughEnv`.
- **Q2** Guests (magic-link contacts, `kind 'guest'`, `userId 'contact:…'`) have **no Ask**: no nav item; the route and pages → 404. Threads FK `auth."user"`.
- **Q3** SSE over a Route Handler `ReadableStream` (`data: <json>\n\n`); the browser uses `fetch` + a stream reader (POST, so no `EventSource`). The turn runs in the handler; `request.signal` abort is ignored for the turn (e1 "turn completes after disconnect") and only stops writes to the stream.
- **Q4** The Ask tool set is every tool whose `channels` include `'mcp'` and whose `mcpScopeOf` is `read`, **plus** the three e8 writes. It excludes the token/grant tools (`create_api_token`, `list_api_tokens`, `revoke_api_token`, `list_oauth_grants`, `revoke_oauth_grant`). `channels` stays an explicit literal per tool (no derived helper), so the channel allowlist test catches drift.
- **Q5** `add_recommendation` writes `source = 'ask'` when `meta.channel === 'ask'`, else `'mcp'` as today.
- **Q6** RLS for `ask_thread`/`ask_message` also requires `app_client_visible(client_id)`, so a user who loses access to the client loses their threads too.
- **Q7** Progress labels are a fixed map in `@cs/ask/src/labels.ts` (tool name → label); unknown → "Working…".
- **Q8** Platform review lives in `@cs/tools/src/platform.ts` style. It uses plain service-role functions (`listReviewableAskThreads`, `getReviewableAskThread`) guarded by `requirePlatformOperator`, not registry tools: it crosses agencies, as the existing platform helpers do.
- **Q9** The guard's `unsure` (no confident verdict after the cascade) proceeds. Only a confident `out_of_scope`/`injection` refuses. Guard errors also proceed (`trace.guard = 'unsure'`).
- **Q10** Assistant names longer than 30 characters are rejected by `update_agency_branding`. Display falls back to "Friday" when blank.
- **Q11** `AskEvent.final.status` gains `'quota'` (the spec's union omitted it; the stored message already uses `status 'quota'`).
- **Q12** `ask_message` references `ask_thread` by `(thread_id, user_id)` (composite FK on `ask_thread UNIQUE (id, user_id)`), so a message can never sit in another user's thread. This tightens the spec's single-column FK.
- **Q13** Web reads of threads and starters are registered tools (`list_my_ask_threads`, `get_my_ask_thread`, `delete_my_ask_thread`, `get_ask_starters`; channel `web` only), per the house rule "web reads are registered tools".

## Review focus
1. **Quota leak to clients:** a client role must never learn counts or quota. Covered by T3 `get_usage refuses client roles`, T8 `quota event carries only the exact copy`, T12 E2E `client at quota sees no numbers`.
2. **Concurrent questions at quota − 1** (two tabs): exactly one passes. T3 `beginTurn race`.
3. **Model cites an id it never received**, or a hallucinated `[ev:…]` in history: dropped, sentence rechecked as uncited. T5 `unknown ids dropped`, T6 `history markers are not citable this turn`.

5. **Confirm clicked twice / Confirm on another user's message / on a cancelled action:** no second write. T8 `double confirm is a no-op`, `foreign message not_found`.

### Task 5: Citations + grounding
**Goal:** Parse `[ev:id]` markers and verify sentences (spec "Grounding").
**Files:** create `packages/ask/src/{citations,grounding}.ts` (+tests); export `supportCheck` from `@cs/engine` if not already exported (it is under `briefs/`; check `index.ts`).
**Interfaces:**
```ts
export const CITATION_PREFIXES = ['ev'] as const;
export function parseCitations(text: string, prefixes: readonly string[], allowed: ReadonlySet<string>):
  { sentences: { text: string; refs: string[] }[] };   // text without markers; refs like 'ev:<uuid>' filtered to `allowed`
export function groundAnswer(ai: Ai, scope: CallScope, draft: string, evidence: ReadonlyMap<string, string>):
  Promise<{ content: string; citations: string[]; removed: number }>;
```
**Behaviour:**
- **Sentence split:** on `.`/`!`/`?` followed by whitespace or end, and on newlines. Keep list bullets as their own sentences. Do not split inside `[ev:…]` or on decimals ("$4.99", "4.5 stars").
- **Markers:** `\[(ev):([0-9a-f-]{36})\]`. A ref not in `allowed` is removed from the text and not counted.
- **Classification:**
  - a sentence with refs → `fact` against the joined text of those refs;
  - a sentence without refs → `interpretation` against all evidence text (joined, each block prefixed with `ev:<id>`);
  - empty evidence and no refs → `interpretation` against `''`.
- **Removal:** sentences failing `supportCheck` are removed; consecutive removed → one `ASK_COPY.noEvidence`. All removed → content = `ASK_COPY.noEvidence`.
- **Output:** `content` re-emits surviving sentences with their surviving markers (original order, original separators/newlines). `citations` = distinct surviving refs in order of first appearance.
- Evidence text is already capped by the caller (4,000 chars per id).

**Tests (TDD):**
- `splits sentences but not decimals or prices`
- `unknown ids dropped`
- `cited sentence checked as fact against its evidence only`
- `uncited sentence checked as interpretation`
- `consecutive removed sentences collapse to one no-evidence line`
- `all removed → only the no-evidence line`
- `citations distinct in first-appearance order`
- `bullets preserved`
- `prefix list honoured (kb ignored when only ev allowed)`

**Done when:** `pnpm --filter @cs/ask exec vitest run citations grounding`.

- **Guard:** `ai.decide('ask_guard_decisions', {question: redactForModel(q)}, {verdict: {type:'choice', options:['in_scope','out_of_scope','injection']}})`. Q9 rules. A refusal persists an assistant message `status 'refused'` and emits `final`.
- **Prompt:** the static system prompt (spec rules) + `cacheControl: true`. Tools come from `registry.describe(ctx, {channel:'ask'})`, sorted by name, mapped to `ChatTool`.
- **History:** the last 10 messages of the thread before this question, excluding `quota|refused|error|cancelled` and `action` rows. Assistant content is passed as stored; `[ev:…]` markers in history are **not** added to this turn's allowed ids.
- **Seed:** when `seedEvidenceId` is set, add the system line "The user is viewing evidence ev:<id>." and pre-allow nothing (the model must call `get_evidence`).
- **Loop:**
  - Each tool call goes to `registry.invoke(ctx, name, JSON.parse(args), {channel:'ask'})`. On `JSON.parse` failure or a `ToolError`, return `{error: code}`.
  - Results go back as a `<data tool="name">…</data>` tool message (`<data`/`</data` escaped as `&lt;data`/`&lt;/data`).
  - Collect evidence ids from every `evidenceIds`/`evidence_ids`/`id` (when the tool is `get_evidence`) in results into `allowed` (`'ev:'+id`).
  - Collect evidence text: `get_evidence` text, else the result row's title/summary, capped at 4,000 characters.
  - `emit(progress)` per call.
- **Write calls:**
  - `ASK_WRITE_TOOLS` → validate the input with the tool's zod input (on failure return `{error:'invalid_input'}` to the model and continue).
  - On success, persist an `action` message (`state 'proposed'`, summary from `actions.ts` per-tool template, e.g. `Save recommendation: "<title>"`), emit `final` with the `action`, and stop.
- **Limits:** step 8 or deadline → one call with `toolChoice:'none'`.
- **Final:** `groundAnswer` → persist the assistant message (`content`, `citations`, `trace`) → `emit(final)` → `UPDATE ask_thread.updated_at`.
- **Errors:** a thrown model error after fallbacks → persist `status 'error'` with `ASK_COPY.error(name)`.
- **Audit:** one audit row for the question (tool `ask_question`, channel `ask`, input hash). Tool calls are audited by the registry.
- **Trace** never holds tool result text.
