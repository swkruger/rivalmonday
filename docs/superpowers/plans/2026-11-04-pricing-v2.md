# pricing-v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Graduated extra-client pricing ($79 → $59), a yearly agency option ($2,290/yr), plan v2 for every agency, a soft agency-plan fence and copy that reads its numbers from data.

**Architecture:** One pure pricing module in `@cs/billing` replaces every `base + extra × seatPrice` formula. Plans store a seat tier list and an optional yearly base. The Stripe gateway creates graduated (and yearly) prices. Agencies carry a billing interval. The sign-up flow gains two fields and the platform sign-ups list gains a non-blocking Check flag.

**Tech Stack:** TypeScript, Drizzle + Postgres (Neon), Stripe SDK (pinned, API 2026-08-26.dahlia), Next.js App Router, Zod, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-04-pricing-v2-design.md` (D1–D11). Brief: `docs/work/pricing-v2.md`.

## Global Constraints
- Money is integer USD cents everywhere; the site uses whole dollars in `PRICING` only.
- Standard v2: base 22900/mo, yearly base 229000, included 3, tiers `[{ upTo: 7, unitCents: 7900 }, { upTo: null, unitCents: 5900 }]`, trial 30, features `['ask','mcp']`.
- Yearly seat tier amount = 12 × monthly tier amount; the discount is on the base only.
- `always_invoice` only on yearly seat increases and the month → year switch; plan moves stay `proration_behavior: 'none'`.
- Web writes via `runTool`; refusals → 404 on pages; new tool ⇒ `ISOLATION_FIXTURES` entry; `upsell_tag` etc. untouched.
- Copy: every new or changed string is drafted in the spec § Copy and signed by the owner in `pnpm copy:review`; new email variant ⇒ `@cs/email` `previews.ts`.
- Site: no `@cs/*` app imports; claims only from the ledger; vendors never named.
- Never edit applied migrations; LF only; commits end with the model's `Co-Authored-By` line.

## Decisions (plan-local, on top of spec D1–D11)
- P1: The glossary (`@cs/core`) cannot import `@cs/billing`, so its `seat` text stays a literal. A `@cs/billing` test pins it to the seed values (`describeTiers`).
- P2: `seed.ts` seeds **standard v1 (history) and v2 (current)** for fresh/test databases. Production gets v2 through the console (`create_plan_version`) and `billing:sync-plan`, followed by the 15c-3b move. These are owner steps, not code.
- P3: The subscription interval is read from Stripe (`price.recurring.interval` of the base line) by the webhook on `checkout.session.completed` / `customer.subscription.updated` and stored in `agency_billing.billing_interval`; the app never infers it.

## Review Focus
1. **An agency at exactly 3, 10 or 11 active clients** gets the tier boundary right ($229, $229 + 7 × $79 = $782, $782 + $59 = $841). Pinned in Task 2.
2. **A yearly agency adding a client mid-year** is charged that client's prorated yearly amount immediately, not a year later. Pinned in Task 4.
3. **A plan move for a yearly agency** swaps to the *yearly* v2 prices. If v2 has no yearly base, the move is refused for that agency rather than silently moving it to monthly. Pinned in Task 4.
4. **A v1 plan's existing per-unit Stripe price** still prices correctly from the one-tier list after the migration (no re-sync, MRR unchanged). Pinned in Tasks 1 and 2.
5. **A support session** cannot switch an agency to yearly, and a pasted URL in the sign-up website field (`javascript:`, over 200 characters) is refused server-side. Pinned in Tasks 5 and 7.

- [ ] Graduated sum (only non-obvious bit):
```ts
let prev = 0, total = 0;
for (const t of tiers) { const cap = t.upTo ?? Infinity; const n = Math.max(0, Math.min(extraSeats, cap) - prev); total += n * t.unitCents; prev = cap; if (extraSeats <= cap) break; }
```
