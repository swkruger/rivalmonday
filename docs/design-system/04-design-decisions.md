# 04 · Design decisions

*The decision log for the Rival Monday design system v1 (proposed 2026-10-23). Each decision records what was chosen, what was rejected, why, its confidence and its exceptions. Evidence IDs → [01](01-screenshot-inventory.md); pattern rows → [03](03-cross-application-comparison.md). **Status: adopted 2026-10-23 (owner: "regard the new design as the mandate"). Binding for all UI; existing screens migrate per [09](09-ai-implementation-playbook.md).***

## Framework

Every conflict was scored against the brief's nine criteria: **usability · visual clarity · fit with the understated direction · density · accessibility (WCAG 2.2 AA) · implementation cost · reusability · fit across page types · evidence**. Two tie-breakers were added for this product:

1. **The owner's saved screens outrank general frequency.** They are the stated taste: 29 screens, 14 of them Plain.
2. **Decisions already recorded in `CLAUDE.md` and `docs/brand/brand.md` are not re-litigated.** Where research points elsewhere, the conflict goes to the owner as an **OD** item instead.

## Fixed inputs (already decided; this system builds on them)

Rival Monday name and wordmark (#2A6BAC + #F5A524) · Friday as an orange pill (#F5A524 / #3B2300) · primary #47A8E7 with white text accepted · secondary #2A6BAC · ink #0B2540 · canvas #F6F9FC · grey panels #EEF2F6 with dark text · Inter · content max-width 1560px · shadcn/ui + Tailwind with brand tokens as CSS variables per agency · hand-written inline-SVG charts validated with the dataviz skill · HighLevel-style context switcher (Platform / Agency / Client) · "Ask Friday" first in the client view · `PageHeader` on every page (title = menu label) · settings under `/agency/settings/*` and `/c/<id>/settings/*` · nothing client-facing names Rival Monday.

## Unresolved assumptions and recommended validation

1. **Colours are not sampled.** No research hex is used directly; all tokens come from brand.md, the existing CSS or new computed values. Validate the tokens in the real app at 100% zoom on a typical laptop.
2. **Dark mode is out of scope.** No evidence was collected. If it is added, step every token for dark surfaces and re-run the dataviz validator with `--mode dark`.
3. **The responsive rules (D-23) come from 3 mobile screens.** Prototype the phone Overview and Friday flows and test them on real devices.
4. **Density** (40px rows, 13px tables) suits agency staff. Owners on phones may need the 44px variant. Check with pilots.
5. **White-label:** agency primary and secondary colours can break contrast. Add an automatic contrast check to the branding settings (warn below 3:1 for UI graphics and 4.5:1 for text on the primary colour).
6. **Two highlighted rivals** may feel limiting. If owners want three, encode the third with a dash pattern (texture) rather than a third hue.
7. **The saved apps in the owner's Mobbin "Apps" group were not readable** through the MCP server. Ask which apps they were if they matter.
