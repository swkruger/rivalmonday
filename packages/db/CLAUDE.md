# @cs/db — working notes
Drizzle schema, migrations, RLS policies/grants, DB clients and test helpers (Neon Postgres).

## Gotchas
- **Drizzle `sql` + JS arrays:** a bare array inside `sql\`...\`` expands to a parameter *list*, not an array. Build arrays with ``sql`ARRAY[${sql.join(items.map((x) => sql`${x}`), sql`, `)}]::uuid[]` ``.
- **Drizzle 0.44 wraps driver errors** (`DrizzleQueryError`); the Postgres message is on `err.cause.message` — use `errorText()` from `@cs/db/test-helpers`.
- **drizzle-kit may order a composite FK before the unique constraint it needs** — reorder the generated SQL by hand when tests fail on migrate (happened in `0002`).
- Migration policy (never edit applied migrations, custom SQL command) is in `docs/gotchas-cross-cutting.md`.
- **RLS patterns:** tenant tables use `agency_id = app_agency_id() AND app_client_visible(client_id)`; global public-data tables use `app_competitor_visible(competitor_id)` and are **written only by the service role** (REVOKE INSERT/UPDATE/DELETE from `app_user`). Revoking changes error text from "row-level security" to "permission denied" — update tests accordingly. The guard test fails if a new public table lacks forced RLS.
- **`app_competitor_visible()` also covers a client's own self business:** it admits a competitor tracked via `client_competitor` *or* that is some visible client's `self_competitor_id`. A self competitor is deliberately never in `client_competitor` (its events are never scored/routed, moves never run on it) — look it up via `client.self_competitor_id`, not a `client_competitor` join.
- **app_user privileges:** the privilege guard test enumerates every public table and asserts an exact allow-list (`client`, `client_competitor`, `competitor_suggestion` UPDATE(status) only). A new tenant table that app_user writes must be added there.
- **`client` UPDATE is column-granted, not table-wide:** `app_user` can `UPDATE` only `name, vertical_id, features, services, keywords, service_area, place_id, score_thresholds, timezone`; `self_competitor_id` and `agency_id` are service-role only. Postgres has no column-level REVOKE finer than the table grant, so a new editable column needs `GRANT UPDATE (col) ON client TO app_user`, never a broader table grant. `client.timezone` defaults to `America/Chicago` (IANA; invalid values fall back via `safeTimezone`); briefs are scheduled in the client's local time.
- **Service-role-only tables** (forced RLS, no tenant policy at all, every privilege revoked from `app_user`, which sees zero rows): `decision_sample`, `decision_label`, `model_batch`, `score_failure`, `contact`, `notification`, `membership`, `invitation`. Access them only via the worker's service-role connection, the `decisions` CLI (`SERVICE_DATABASE_URL`) or `@cs/tools`' role-checked functions.
- **Captures and evidence are immutable at the DB level:** triggers block UPDATE/DELETE for every role; only `capture.legal_hold` may change. Competitors/tracked pages with captures can't be deleted (FK RESTRICT). Retention deletion is a Phase 7 feature.
- **`EMBEDDING_DIMENSIONS`** (`@cs/db`, = 512) is the single source of truth for embedding width — matches `vector(512)` columns and `dimensions: 512` in `ai.yaml`'s `embeddings` task. The engine's output row is `changeEvent` (table) / `ScoreFactors` (stored on `event_score`) — not "eventChange".
- **`competitor.meta_page_id` is gone (migration `0021`):** use `competitor.meta_page_ids` (plural, several Meta pages per franchise competitor).
- **`event_change` has `unique(change_id)`:** a change has at most one event — don't write "any linked event" logic.
- **`search_tsv` columns are SQL-only** (migration `0039`, generated `tsvector` + GIN on review, recommendation, brief_item, event, alert): they are not in the Drizzle schema, so query them with `sql` and don't let `drizzle-kit generate` drop them. Page search is vector-only.
- **`withTenant` sets `app.user_id` and `app.role`** besides the agency/client GUCs (SQL `app_user_id()`, `app_role()`); token-table RLS depends on them, so a `TenantScope` built without `userId`/`role` sees no tokens.
- **`api_token.token_hash` is unreadable by `app_user`** (column-limited SELECT; only `UPDATE (revoked_at)` on `api_token` and `oauth_grant_binding`). Token lookup by hash, inserts and bindings are service-role; `SELECT *` as `app_user` fails with "permission denied".
