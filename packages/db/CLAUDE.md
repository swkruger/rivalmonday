# @cs/db — working notes
Drizzle schema, migrations, RLS policies/grants, DB clients and test helpers (Neon Postgres).

## Gotchas
- **Drizzle `sql` + JS arrays:** a bare array inside `sql\`...\`` expands to a parameter *list*, not an array. Build arrays with ``sql`ARRAY[${sql.join(items.map((x) => sql`${x}`), sql`, `)}]::uuid[]` ``.
- **Drizzle 0.44 wraps driver errors** (`DrizzleQueryError`); the Postgres message is on `err.cause.message` — use `errorText()` from `@cs/db/test-helpers`.
- **drizzle-kit may order a composite FK before the unique constraint it needs** — reorder the generated SQL by hand when tests fail on migrate (happened in `0002`).
- Migration policy (never edit applied migrations, custom SQL command) is in `docs/gotchas-cross-cutting.md`.
- **RLS patterns:** tenant tables use `agency_id = app_agency_id() AND app_client_visible(client_id)`; global public-data tables use `app_competitor_visible(competitor_id)` and are **written only by the service role** (REVOKE INSERT/UPDATE/DELETE from `app_user`). Revoking changes error text from "row-level security" to "permission denied" — update tests accordingly. The guard test fails if a new public table lacks forced RLS.
- **`app_competitor_visible()` also covers a client's own self business:** it admits a competitor tracked via `client_competitor` *or* that is some visible client's `self_competitor_id`. A self competitor is deliberately never in `client_competitor` (its events are never scored/routed, moves never run on it) — look it up via `client.self_competitor_id`, not a `client_competitor` join.
- **app_user privileges:** the privilege guard test enumerates every public table and asserts an exact allow-list (`client`, `client_competitor`, `competitor_suggestion` UPDATE(status) only). A new tenant table that app_user writes must be added there.
- **`client` UPDATE is column-granted, not table-wide:** `app_user` can `UPDATE` only `name, vertical_id, features, services, keywords, service_area, place_id, score_thresholds, timezone`; `self_competitor_id` and `agency_id` are service-role only. Postgres has no column-level REVOKE finer than the table grant, so a new editable column needs `GRANT UPDATE (col) ON client TO app_user`, never a broader table grant. `client.timezone` defaults to `America/Chicago` (IANA; invalid values fall back via `safeTimezone`); briefs are scheduled in the client's local time.
- **Service-role-only tables** (forced RLS, no tenant policy at all, every privilege revoked from `app_user`, which sees zero rows): `decision_sample`, `decision_label`, `model_batch`, `score_failure`, `contact`, `notification`, `membership`, `invitation`. Access them only via the worker's service-role connection, the `decisions` CLI (`SERVICE_DATABASE_URL`) or `@cs/tools`' role-checked functions.
- **Captures and evidence are immutable at the DB level:** triggers block UPDATE/DELETE for every role; only `capture.legal_hold` may change. Competitors/tracked pages with captures can't be deleted (FK RESTRICT). Retention deletion is a Phase 7 feature.
- **`EMBEDDING_DIMENSIONS`** (`@cs/db`, = 512) is the single source of truth for embedding width — matches `vector(512)` columns and `dimensions: 512` in `ai.yaml`'s `embeddings` task. The engine's output row is `changeEvent` (table) / `ScoreFactors` (stored on `event_score`) — not "eventChange".
- **`competitor.meta_page_id` is gone (migration `0021`):** use `competitor.meta_page_ids` (plural, several Meta pages per franchise competitor).
- **`event_change` has `unique(change_id)`:** a change has at most one event — don't write "any linked event" logic.
- **`search_tsv` columns are SQL-only** (migration `0039`, generated `tsvector` + GIN on review, recommendation, brief_item, event, alert): they are not in the Drizzle schema, so query them with `sql` and don't let `drizzle-kit generate` drop them. Page search is vector-only.
- **`withTenant` sets `app.user_id` and `app.role`** besides the agency/client GUCs (SQL `app_user_id()`, `app_role()`); token-table RLS depends on them, so a `TenantScope` built without `userId`/`role` sees no tokens.
- **`api_token.token_hash` is unreadable by `app_user`** (column-limited SELECT on `api_token`; full SELECT on `oauth_grant_binding`, both row-limited by RLS; only `UPDATE (revoked_at)` on the two tables). Token lookup by hash, inserts and bindings are service-role; `SELECT *` as `app_user` fails with "permission denied".
- **`kb_chunk` RLS has no status check** (0046): chunks exist only for published articles and carry copied `level`/`agency_id`/`client_id`/`client_visible`; `kb_chunk.search_tsv` is SQL-only like 0039's. App roles get SELECT only on `kb_*`; agency rows with `client_visible=false` are hidden when `app_role()` is a client role or unset.
- **Renumbering a branch's migrations after `main` took its numbers** (Phase 9, 2026-10-15): rename SQL highest-first; rebuild `meta/_journal.json` (main's entries byte-equal, then ours) with every `when` strictly after main's last — the migrator silently skips entries whose `when` is older than the latest applied one; rebuild each snapshot as a three-way merge with main's latest snapshot (first `prevId` = main's last `id`); prove with `pnpm --filter @cs/db generate` = "No schema changes" and `drizzle-kit check`. A DB that applied the old numbers needs a reset.
- **A column holding a Better Auth user id (`*_by`, `last_changed_by`, `invited_by`, `decided_by`) must be `text`, not `uuid`** — Better Auth ids aren't UUIDs; Phase 11 needed fix migrations 0069 and 0071 (13b's 0076 `rank_scan.requested_by` likewise). postgres-js also rejects a raw `Date` inside `db.execute(sql\`…\`)` — bind `${d.toISOString()}::timestamptz`.
- **Schema changes use plain `pnpm --filter @cs/db generate --name=<x>`** (writes SQL + snapshot); `--custom` only for SQL Drizzle can't express (data moves, RLS, grants). A `--custom` migration for a column/index change leaves the snapshot stale, so the next generate re-emits it (15b, `0080`).
- **`pgboss` is owned by `cs_worker`** (migration `0081`): grants name tables explicitly, never `ON ALL TABLES` (owner-created queue partitions break it); the worker re-grants via `ensureQueueGrants`. `predeploy-check` runs before every prod migrate (`docs/DEPLOY.md`).
- **Archived = deleted (0082):** `client`/`agency.archived_at` is service-role-only (not in the `client` UPDATE grant). `app_client_visible()` (0083) is false for an archived client via the SECURITY DEFINER `app_client_archived()` (owner bypasses RLS; EXECUTE `app_user` only), so every tenant policy built on it hides that client's rows and refuses writes; `client_isolation` also has `archived_at IS NULL`. Not covered: policies that skip `app_client_visible` (scope-`all` ledger/audit, agency-level rows) and every service-role reader, which needs its own filter. The five ledger/audit FKs (`audit_log.agency_id`, `llm_call`/`vendor_call` `agency_id` + `client_id`) were dropped so purge can delete a tenant and keep the rows detached.
- **Data-backfill migrations are tested by re-running their SQL** (the test DB is already migrated): put idempotent, old-shape-filtered `UPDATE`s after a `-- backfill:start` block and have the test split on `--> statement-breakpoint` and re-run from that marker (`topic-rename.test.ts`, `billing.test.ts`). A `--custom` rename leaves the snapshot stale: hand-align `meta/<n>_snapshot.json` until `generate` says "No schema changes" (15b-3, `0084`).
- **Spend guard (7b1):** `llm_call`/`vendor_call.cost_usd` is `numeric(14,6)` with `mode: 'number'` (0089; read as JS numbers, aggregate with `::float8`; sub-micro costs round to 6 dp). Ledger rows carry `competitor_id` for shared collection spend; `splitByCompetitor` writes one row per competitor in `scope.competitorIds`, and `spendByClient` adds an equal share of each shared row to every current tracker (`TRACKERS_CTE`, O11); `provider` in `SPEND_GUARD_EXCLUDED_PROVIDERS` (Jev) is skipped, never inline `'jev'`. `spend_guard_event` (0090) is service-role only with no FKs (rows outlive a purge); `client_reached`/`client_paused` are unique per client and month. State lives in `platform_setting` keys `ai_guard_state` / `spend_guard_settings` (`lockAiGuardState` = `FOR UPDATE` re-read). `client.spend_paused_at` is service-role only; recurring client work filters `clientWorkAllowed` (= `clientServiceable` + `spend_paused_at IS NULL`), seats/billing/dashboards keep `clientServiceable`.
