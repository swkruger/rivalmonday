# @cs/collectors — working notes
Data collection: web crawling/capture, vendor clients (DataForSEO, Apify, ScrapeCreators), GBP/reviews/ads/jobs/rankings, competitor discovery, scheduling and evidence privacy.

## Gotchas
- Crawler conduct rules and worker-is-one-replica are in `docs/gotchas-cross-cutting.md` — read them before touching crawling.
- **Vendor quirks (live-verified):** DataForSEO can answer 200 with an OK envelope but a task-level error (check `isDfsOk` per task); `task_get` repeats the cost but isn't billed (ledgered at $0); `data.tag` echoes our competitor id (tasks are mapped by tag); Apify returns an error *item* for pages with no ads; `ads_search` by domain returns other advertisers' creatives (filtered by name); owner replies greet reviewers by first name (redacted).
- **Collection claims skip untracked competitors:** `claimDueSources`/`claimDuePages` stop offering a competitor's vendor/web sources the moment its last `client_competitor` row is removed; the rows stay `active` and resume being claimed when any client re-adds it (no re-creation). Exception: a self-business competitor (`client.self_competitor_id`) always has claimable `gbp`/`reviews` sources.
- **Changing a client's place id unlinks its old self-business row:** `update_client_profile` nulls `client.self_competitor_id` (service Db) whenever the merged `placeId` differs from the stored one (including clearing to `null`); the next `ensureSelfCompetitor` tick re-links or creates the right row, so paid `gbp`/`reviews` collection stops hitting the old business.
- **`patchReusedCompetitor({ backfill: false })` for anything a human typed:** `add_competitor` reusing another agency's global competitor row renames it (no private client name exposed cross-tenant) but must never write the caller's typed `placeId`/`domain` onto that shared row — that can redirect another agency's paid collection. The suggestion accept tools (vendor data) backfill by default (`backfill: true`); any new caller passing user-typed identifiers must pass `{ backfill: false }`.
- `redactForModel` (`src/evidence/model-privacy.ts`) is the required redaction at every model boundary — rule in `docs/gotchas-cross-cutting.md`.
- **SSRF guard (`net/guard.ts`) is the only fetch path for user- or page-supplied URLs** (robots, KB import, renderer). The renderer routes every hop through `route.fetch` (no redirect following by the browser), deletes `SharedWorker`, and **aborts `media`, `font` and `other` requests**, which also drops beacons, pings and CSP reports. A DNS rebinding race between our check and Chromium's connection remains (backlog).
- **Host limiter and captures (7c2):** `HostRateLimiter` (`web/rate-limit.ts`) is shared by pages and robots fetches; it keeps `last`, a deferral `cursor`, a per-host `locked` flag and the largest **learned** Crawl-delay per host (so a null-delay request such as a robots re-fetch is still spaced by it). `nextSlotIn` is a pure query; only `wait`/`deferIn` reserve and learn. `PoliteRenderer.renderOrDefer` (cap `MAX_CAPTURE_WAIT_MS` 10 s) returns `deferred` instead of sleeping; `capturePage` surfaces `{ status: 'deferred', retryInMs }`, and a caller must re-enqueue (the worker uses `capture:<id>` singleton keys; `collect-once` sleeps and retries up to 10 times). `RobotsPolicy` takes the limiter as its 5th constructor arg, dedupes concurrent loads per origin and offers `peek` (cache only, TTL-aware).
- **Rehearsal fixtures (7c2):** `vendors/fixture-fetch.ts` answers DataForSEO/Apify/ScrapeCreators/Stadia at $0 (DataForSEO task ids are **stateless**: they encode what `task_get` needs, so a worker restart does not strand tasks posted since); `rehearsal/fixture-sites.ts` serves fixture sites (`fx5` has `Crawl-delay: 30`; variant by `hash(group, isoWeek) mod 10`, mutating from Wednesday 00:00 UTC). `allowlistedAssert(allow, inner?)` (`net/guard.ts`) is **fail closed**: an empty or `,`-only list allows nothing. Only the worker's staging switches (`apps/worker/CLAUDE.md`) turn these on.
