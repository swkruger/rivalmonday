# @cs/evals — working notes
Record/replay eval harness (phase 7c1): labelled case sets in `data/<suite>.jsonl` (changes, reviews, briefs, ask), recorded model replies in `cassettes/<suite>.json`, accuracy baselines in `baselines/<suite>.json`. CI runs `pnpm eval:replay` (offline, $0); `eval record` and the `evals-live` workflow spend real money under a cap. Commands, labelling and spend: `docs/OPS.md` § Evals.

## Gotchas
- **Re-record triggers (each one is a replay miss, exit 1 naming the suite):** the task's `ai.yaml` entry (model, fallbacks, max_tokens, ...); any prompt; an ask-channel tool's description, input schema or output shape (`packages/tools/src/`); the isolation world (`packages/db/test/`: a new table adds world rows tools can return); Ask turn/grounding code (`packages/ask/src/`); the engine `supportCheck`/verifier prompt (briefs and Ask). Re-record that suite in the same PR. A branch merging after 7c1 that touches any of these (e.g. phase-15c2b) runs `pnpm eval:replay` after rebasing and re-records the missing suite. `evals-live` runs on PRs touching those paths (incl. `packages/tools/src/`, `packages/db/test/`).
- **Ask clock is pinned process-wide (R14 revised):** `askRunner.run` installs `pinClock(ASK_TODAY)` (`src/clock.ts`, a `Date` shim; timers untouched) before seeding and removes it in `finally`; `askRunner.today` pins the cassette to the same instant. Tool outputs like `get_rating_trend`'s `YYYY-MM` buckets are not normalised by the cassette, so never read the wall clock elsewhere in the suite. DB `now()` defaults stamp the real clock and tools return them (`list_client_competitors.date`, `addedAt`, `list_ads`), so `shiftDbStamps` (`suites/ask/seed.ts`) moves every timestamp the DB stamped during seeding onto the pinned clock (capture/evidence are immutable and skipped; nothing returns their `created_at`). A new tool returning a DB-default timestamp of a row created during the turn itself would still leak. Briefs are pinned via `SuiteRunner.today` only.
- **Ids are builder-generated:** `contactLeaks` exempts a case's own top-level `id`; the build refuses to write a file where contact details survive `redactForModel`.
- **Foreign-id cross-tenant Ask path is covered only by the scripted unit test:** ids written into questions are redacted as phone-like, so a live case cannot carry one.
- **`src/cli/load-env.ts` must stay the CLI's first import** (it loads the root `.env` before any module reads env).
- **The Ask suite truncates the test DB:** never run it alongside another test run on the same DB (`prepareTestDb` refuses any non-`_test` URL). The reverse bites too: any vitest run's global setup empties the worktree DB, so a focused web/package test during `eval record` deletes the world mid-turn (`ask_message` FK `ask_message_agency_id_agency_id_fk`, "Key is not present in table agency"; 18c-1 lost a fill run that way). Suite errors now print the cause chain and live spend.
- **Budget stop in record mode loses the recording:** the cassette flushes only when the suite completes. Raise `--max-usd` and re-run.
- **Single-case re-record is ad hoc today** (no `record --case`); re-record the whole suite, or `record --fill` to go live only on cassette misses (stored replies reused, so an old passing answer stays).
- **Injection canaries are codes, not claims:** a good refusal may quote the planted claim to warn the user (`ask-inject-09` failed 7 of 10 live on that), so a canary must be something only an obedient answer would repeat.
- **Pre-labels are LLM/template guesses:** headline decision metrics count only owner-confirmed labels; unconfirmed ones report as `prelabel_agreement.*`. Changes/reviews cases are report-only (`blocking: false`); B1-B3 (briefs, ask) block. In replay, `case_errors > 0` is a blocking `E` failure (replay is deterministic); live keeps errors report-only.
- **Eval topics are the repo YAML seed topics**, not production's AM-approved discovered ones.
- **Live record cost (2026-10-26):** a full `ask` record ≈ $1.6 and ~1 h (50 cases run sequentially, ~6 Sonnet 5 calls/case at ~12k prompt tokens each) — when only decision/Jev tasks changed, use `record --fill` (jev-openrouter: $0.07). OpenRouter 402 `in_flight_budget_exhausted` = account balance too low: stop, the owner tops up; retrying burns money on cut-off turns.
- **`--fill` saves money only when a few calls miss:** an ask-channel tool's description/schema/output change alters every Ask request key, so `--fill` goes live on all ~360 calls, hits its cap and saves nothing (2026-11-10: $1.85 lost). Do a full `record --max-usd 5` first, then `--fill` only to patch the turns that failed with invalid JSON (they are not stored, so replay misses them).
- **Intermittent Ask replay miss = an unordered tool query:** every case reseeds, so tied rows (same timestamp) can come back in a different order and change the request key. Break ties on `id` in the tool's `ORDER BY` and pick the direction that matches the recorded cassette (no re-record); `193437be` was `get_competitor_timeline` (fixed 2026-11-07). To find the case, temporarily dump the normalized request in `cassetteKey`'s caller and diff a failing run against a passing one.
