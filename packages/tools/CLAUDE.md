# @cs/tools — working notes
The tool registry: every read/write the web app (and later MCP) performs, with role/feature checks, audit logging and the workspace (event/move/evidence) readers.

## Gotchas
- **`ToolDeps`'s optional members fail closed:** `enqueueOf(deps)` throws `ToolError('internal')` when `deps.enqueue` is absent; a tool needing `deps.delivery` that finds it `null`/absent refuses with an `invalid_input` message naming `APP_URL`/`LINK_SIGNING_SECRET`; `deps.webMonitoring` defaults to `false`, so an unconfigured web app never enqueues `discover-pages` and always refuses `add_tracked_page` — check `WEB_MONITORING_ENABLED` first for any "why isn't it crawling" question.
- **Settings writes are tools:** the 11 settings mutations (`invite_member`, `revoke_membership`, `revoke_invitation`, `update_agency_branding`, `add_webhook`, `set_webhook_active`, `add_client_recipient`, `deactivate_recipient`, `update_client_delivery`, `set_my_notification_pref`, `update_my_contact`) are registered in `src/tools/settings.ts` wrapping the service functions — the registry audit-logs the mutation, so calling the service function directly silently skips the audit row. Reads (`listTeam`, `getAgencyBranding`, `listWebhooks`, `listClientRecipients`, `myNotificationSettings`) are plain service functions.
- **Operator tools check `PLATFORM_ADMIN_EMAILS` on every call:** `requirePlatformOperator(deps, ctx)` runs inside each of `list_decision_reviews`, `resolve_decision_review`, `list_theme_proposals`, `decide_theme_proposal`; the sidebar's `isPlatformOperator` flag only decides what's *shown*. A crafted post from a non-operator gets `permission_denied` → 404.
- **`hasFeature` vs the registry's feature check:** both bypass the flag for agency roles. Tools enforce through the registry's `feature`; pages call `hasFeature(ctx, 'dashboard')` and 404 otherwise. Nav items are flag-driven (`NavRoleFlags.dashboard/alertRules/mcp/manageCompetitors`).
- **Event visibility lives in `workspace/scope.ts`:** decision 3's rule (an `event_score` row for the client, competitor currently tracked, `retracted_at IS NULL`) is defined once; every new event reader uses `clientEvents()` + `eventJoin`. `liveEventCount` lives there too (moved from `tools/moves.ts` to avoid an import cycle with `pressure.ts`); `pressureByClient` counts only moves with a live event.
- **Evidence access (decision 7) needs no `dashboard` flag:** evidence is accessible if tracked now, or cited by a visible alert/brief item (clients: delivered alerts, approved/sent briefs, `active` items only). `get_evidence.citedBy` is `[]` without `dashboard`. The evidence route never serves `html`/`vendor_json` (untrusted competitor markup) — only `screenshot` and `text`.
- **`list_brief_queue`:** per visible client, newest brief with `delivery_date ≥ today − 7 days` (UTC) **plus** any older brief still `ready`; ready briefs sort first (so a never-approved quiet brief from weeks ago still shows).
- **`get_usage` counts only client-attributed ledger rows:** `sum(cost_usd)` of `llm_call`/`vendor_call` rows carrying that `client_id`, current UTC month. Shared collection (`agency_id` set, `client_id` NULL — competitor GBP/reviews/ads, most engine stages, a prospect snapshot's GBP/ads pulls) is not attributed; allocating it is Phase 7.
- **The package index doesn't re-export DB-touching workspace internals:** it exports only labels, word-diff and `evidenceContentType`/`EVIDENCE_CONTENT_TYPES`/`ServableEvidenceKind`; inside the package import workspace modules by path.
- **Tests share `src/tools/workspace-fixtures.ts`:** import it; it opens and closes the test DBs itself.
- **Channels (MCP):** a tool is web-only unless it sets `channels` (`['web','mcp']`, or `['mcp']` for `add_recommendation`; the Ask set (mcp read tools + `ASK_WRITE_TOOLS`) also lists `'ask'`); the exact lists are asserted in `tools/channels.test.ts`, so a new MCP tool must be added there. `mcpScope` defaults from `permission` (`mcpScopeOf`); `audit: 'skip-web'` drops web audit rows only (MCP calls are always audited). Handlers get `meta` (`{channel, tokenId}`) as 4th arg: use `pageOf`/`detailOf` (summary default and limit <= 50 off-web).
- **d12:** any captured/competitor text a handler returns on a non-web channel goes through `forChannel(meta, text, businessNames)` (`workspace/model-text.ts` → `redactForModel`), never bare `redactContactInfo`. `upsell_tag` stays out of client-role results.
- **Hidden tools look unknown:** the registry throws the same `not_found` for unknown and invisible tools (audit keeps `permission_denied`), so handler-level `permission_denied` is distinguishable: keep such tools off `mcp`.
- **`search`/`fetch` need deps:** `embedQuery` only in `dev` (else full-text only; pages are vector-only) and `evidenceStore` for evidence text.
