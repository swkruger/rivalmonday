# @cs/ai — working notes
Model access: OpenRouter chat/embeddings, Jev decisions with LLM fallback cascade, shadow sampling, Anthropic Message Batches, `ai.yaml` task config.

## Gotchas
- **Jev API:** `POST https://api.typesafe.ai/v1/systemone`, model `jev-latest` (returns `jev-1.13.0`); noul has no confidence field (derived); score = average, level = argmax.
- **OpenRouter JSON-schema tasks need a ZDR endpoint that supports structured outputs:** `anthropic/claude-sonnet-5` had none on 2026-10-03 (404 "No endpoints found"), nor did `openai/gpt-5-mini`; the writers use `anthropic/claude-sonnet-4.6` → `anthropic/claude-haiku-4.5`. Fake-AI unit tests can't catch this — probe live before changing a JSON-schema task's model.
- **Anthropic batches:** with `ANTHROPIC_API_KEY` set, nightly topic discovery uses Message Batches (`anthropic-batch.live.test.ts` passes); a rejected submit falls back to the synchronous OpenRouter path, counted as `batchFallbacks` in the `[reviews-nightly]` log line.
- **`AI_SHADOW_RATE` costs real money:** setting it (0–1) overrides every task's `shadow_rate` and forces that fraction of calls to also ask the LLM, ledgered as `<escalate_to>:shadow` (in practice `llm_decisions:shadow`). Only for a deliberate, budgeted live measurement run (e.g. `AI_SHADOW_RATE=1 pnpm --filter @cs/worker engine-once …`), never left on. Shipped defaults are low (0.05 generally, 0.02 for `review_decisions`).
- **Shadow mode is not the cascade, failure-wise:** a sampled call asks Jev and the LLM in parallel. If Jev answers below threshold and the shadow LLM call fails, the decision returns Jev's low answer with those keys in `needsReview` — it does **not** throw like the non-shadow cascade (only both providers failing throws). The shadow LLM call is ledgered as `llm_decisions:shadow` even when its answers were used, so `llm_decisions` rows undercount real fallback use by the sampled fraction — add the two when costing escalations.
- **Config file lookups:** use `path.join(dirname(fileURLToPath(import.meta.url)), …)`, never `new URL('<relative>', import.meta.url)` — Turbopack (apps/web) can't resolve the latter (see `apps/web/CLAUDE.md`).
- **Check a new model's parameters before adding it to a tool or JSON task:** `require_parameters: true` is sent with tools and JSON schemas, so an unsupported parameter (sonnet-5 accepts no `temperature` on any endpoint) makes OpenRouter skip that model silently and every call runs on the fallback. `GET /api/v1/models/<id>/endpoints` lists `supported_parameters`; the ledger's `model` column shows which model actually answered.
- **Spend guard and abort (7b1):** `createAiFromEnv(..., guard)` makes every `chat`/`decide`/`embed`/`submitBatch` call `guard.assertAllowed(scope)` first and throw `AiPausedError` (`reason` `platform` or `client`) with no ledger row; the guard (`createAiGuard` in `@cs/db`, 30 s cache, a read failure allows the call) is shared per process, and `collectBatch` is never refused (it only collects). Handlers must rethrow `AiPausedError`, not swallow it as a model failure. `ChatRequest.signal` reaches `postJson` (aborted = non-retryable, no sleep); Ask aborts non-final calls at the deadline and gives the final call its own 45 s timeout.
