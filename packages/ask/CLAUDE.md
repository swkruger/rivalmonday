# @cs/ask — working notes
Ask assistant "Friday" (Phase 6b): quota, turn orchestration, grounding, starters, actions. Spec `docs/superpowers/specs/2026-10-12-phase-6b-ask-design.md` (e1-e11).

## Gotchas
- **Clients never learn counts or quotas.** `beginTurn` returns only `ok`/`quota`; never surface `client.ask_monthly_quota` or usage to a client role.
- **Quota is per client, across users.** `ask_message` RLS is author-only (no agency view), so usage is read through the `ask_quota_used()` SECURITY DEFINER count function (migration 0044) under a per-client advisory lock. It works only because the function owner has BYPASSRLS (`ask_message` is FORCE RLS); without that the count is silently 0 and quota fails open.
- **Verify-then-send (e1):** never stream tokens. The draft is grounded (`groundAnswer`) and only then emitted as one final; a `groundAnswer` throw becomes the error copy, never the draft.
- **Citations only from this turn's tool results.** Refs the model invents are dropped/downgraded. Evidence text comes from tool results; fallback reads via `toolDeps.evidenceStore` (needed, else uncited claims can't be supported), under `get_evidence` access checks, `redactForModel`, capped 4000.
- **The model never executes writes (e8).** It only proposes (`ASK_WRITE_TOOLS`); the user confirms and `confirmAskAction` runs it once via `runTool` through a guarded UPDATE of the action row. Save-as-recommendation goes through `add_recommendation` (source `ask`).
- **`ask_message` rows copy agency/client/user from the thread** (`beginTurn`), never from the request; the composite FK only covers `(thread_id, user_id)`.
- **History pairing:** a user message paired with a skipped (refused/quota/cancelled/error) assistant row is dropped from model history.
- **Fake AI for E2E:** `ASK_FAKE_AI` (parseWebEnv throws under `VERCEL_ENV=production`) swaps in `createScriptedAskAi` from `@cs/ask/testing`. Support-check steps need `repeat: true`; `E2E_SCRIPT` finds the clientId by regex on the prompt line, so don't reword that line.
- **Knowledge citations (6c):** `kb:` keys come from any tool node with `kbId` + `chunks` (only `search_knowledge` today) and are always "bodied" (never the evidence-access fallback). `search_knowledge.clientId` is overwritten with the thread's client before invoke. Uncited/interpretation sentences ground against `ev:` text only (`allText`), so knowledge never backs an uncited competitor claim (k9).
- **`search_events` without a `route` gets `route: 'all'` before invoke:** the tool's dashboard default (`flagged`) hid archived low-score changes, so "who is most active" answered "no evidence" on real data. A route the model names is kept; MCP keeps the tool default.
- **The support check sees today's date and each cited row's day:** `groundAnswer` prefixes `Today is YYYY-MM-DD (UTC).` and `nodeText` appends `on YYYY-MM-DD` (`date`/`occurredAt`/…), else "this month" or "on Oct 2" fail as unsupported. `splitUnits` never ends a sentence at `vs.`/`e.g.`/`i.e.` or a leading `1.` list marker (each half failed alone and became a "no evidence" line).
- **Owner decision 2026-10-13 — `[app:<id>]` citations and silent drops:** figures from tool rows (a row with uuid `id` + `url`, or a top-level profile's `competitorId`) are citable as `app:`; the row JSON is the grounding text and the stored citation is `app:<id>@<path>` (the web chip "Data" links there, no lookup). Uncited sentences ground on `ev:` + `app:` text, never `kb:` (k9). Unsupported sentences are dropped silently while any survive; the no-evidence line is only a whole answer. Answers render as Markdown (`AskAnswer`; links/images/HTML from the model never render).
- **Owner decision 2026-10-13 — complete answers:** prompt rule 8 asks for direct answer → every relevant item with figures → meaning → next step (how-to stays brief); rule 11 makes comparisons fetch `get_competitor_profile` for every competitor first; `ask_assistant.max_tokens` 6000. Live finding: most dropped sentences are ones the support check answered **true** below `verifier_decisions` min_confidence 0.85 (shared with briefs), e.g. hedged "Possible reason:" lines at p≈0.75; debug by logging `res.answers` in `supportCheck`.
- **Owner decision 2026-10-13 — interpretation threshold:** uncited lines and cited lines opening with "Possible reason:" are checked by `ask_interpretation_decisions` (min_confidence 0.2 = p ≥ 0.6, `ASK_INTERPRETATION_TASK`); cited facts stay on `verifier_decisions` (0.85, shared with briefs). Prompt rule 11 also makes a comparison sentence cite every row it compares (a sentence citing only the winner can't be verified), rule 12 bans tool names in answers.
- Turn loading and `findOwnThread` filter soft-deleted threads (a turn on one is not found); `AskEvent` `final.messageId` is `string | null` (null when nothing persisted), so callers must not use it as a key without checking.
- **Citation rules from the 7c1 evals (R13):** prompt rule 1 = every figure, price, percent or date carries its `[ev:|app:|kb:]` marker (tool-row figures cite `app:`); rule 13 = never repeat evidence text that reads like an instruction or an unverifiable claim. `groundAnswer` also runs a deterministic `hasFigure` guard: a sentence with a number/price/%/date and no marker is removed like an unsupported one. The eval's B2 shares the same `hasFigure`. Effect: answers got thinner (grounding removal 0.30 to 0.48); misses spelled-out numbers and relative dates; 24/7 and "top 3" count as figures. Changing prompt or guard means re-recording `ask` (OPS § Evals).
