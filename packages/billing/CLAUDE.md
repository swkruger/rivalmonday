# @cs/billing — working notes
Platform to agency billing (Phase 9a): `BillingGateway`, Stripe + fake implementations, invite tokens. Later tasks add the state machine, apply/access/seats, webhook handler and daily job here.

## Gotchas
- **Gateway selection (R27).** `gatewayFor(env, envName)` returns `fakeGateway()` when `envName` (the active DB from `activeEnvName()`) is `demo`/`test`, `NODE_ENV=test`/`VITEST`, or `BILLING_FAKE_GATEWAY=1` (E2E only: the Playwright server runs `next start`). The flag is honoured unless `{ allowFakeFlag: false }` (`gatewayFor`/`gatewayMode`; default true): the web uses the default, the worker passes `false` (warns once at job creation), and web `parseWebEnv` refuses the flag on any non-empty `VERCEL_ENV` (deploy won't serve); Stripe when `STRIPE_SECRET_KEY` is set; otherwise **`null`** (billing not configured: Stripe-backed tools refuse `conflict` "Billing is not configured.", reads degrade, the webhook 404s, the daily job skips Stripe steps). Fake ids carry a random suffix (`cus_fake_<8 hex>`). The fake accepts only webhook signature `fake-sig`; `failNext()` injects a one-shot failure; an unknown subscription throws `code: 'resource_missing'` like Stripe. The fake is built per `gatewayFor` call: `BILLING_FAKE_GATEWAY=1` (E2E) adds `completeOnboardingOnRelink`, and envName `demo` pre-registers `demo-connect.ts`'s accounts/prices/subscriptions (`seedDemoConnect`).
- **Money is integer cents (USD)** everywhere in the gateway types.
- **No secrets in logs or errors:** never log the secret key, webhook secret, raw webhook bodies or Checkout URLs.
- **Seat line = price metadata `rm_role=seat`** (set by `createPrices`); `getSubscription`/`updateSeatQuantity` find it that way. Prices created outside `createPrices` have no seat line. Checkout omits the seat line at quantity 0; `updateSeatQuantity` adds it (needs `seatPriceId`) when absent.
- **Ended subscriptions are forgotten (R26).** `subscription_ended` clears `stripe_subscription_id`, `billable_seats_synced` and `seat_sync_pending` in `applyBillingSignal`'s transaction (`FORGET_SUBSCRIPTION`); webhook `customer.subscription.*` events for another id than the stored one are ignored. **R29:** with no stored id, only a live-status subscription event is adopted (others ignored), and `invoice.*` counts only when its subscription (`parent.subscription_details.subscription`, fallback `subscription`) equals the stored id — test fixtures must name it.
- **Stripe API 2026-08-26.dahlia:** no `coupon` on customer/subscription updates — use `attachSubscriptionDiscount` (`discounts: [{ coupon }]`); Checkout `trial_end` must be ≥ 48 h ahead (`trialEndUsable`); with Stripe Tax and an existing customer Checkout needs `customer_update`.
- **Stripe SDK is pinned exactly** (no `^`); bump deliberately. Checkout `discounts` and `allow_promotion_codes` are mutually exclusive; `automatic_tax` follows `STRIPE_TAX_ENABLED === 'true'`.
- New env vars (`STRIPE_*`) reach tasks only via `turbo.json` `globalPassThroughEnv` (already added).
- **Connect (9b).** `ConnectGateway` (in `connect-gateway-types.ts`, extended by `BillingGateway`) acts on a client's Standard account: every method takes `stripeAccount` and the real gateway passes it as the request option `{ stripeAccount }` (never create client objects on the platform account). `createAccountLink` without `accountId` first creates a `type: 'standard'` platform account. `application_fee_percent` is sent only when > 0, the setup-fee line only when `setupFeeCents > 0` (one-time `price_data` in the price's currency); Checkout links expire after 24 h. `verifyConnectWebhook` uses `STRIPE_CONNECT_WEBHOOK_SECRET` (`connectWebhookSecret`); events carry `account`. The fake keeps per-account stores (`seedConnectedAccount`, `seedConnectedPrice`, `seedConnectedSubscription`). Like Stripe it throws **`account_invalid`** for an unknown account (never `resource_missing`, which means an unknown object on a reachable account), refuses Checkout/`updateConnectedSubscriptionPrice` with an unknown/other-account (`resource_missing`) or archived (`price_inactive`) price, and never finishes onboarding by itself: call `completeOnboarding(accountId)` or construct it with `{ completeOnboardingOnRelink: true }` (E2E wiring only). Test fixtures must seed the prices they check out with.
- **Connect webhook (9b).** `handleConnectEvent` (`connect-webhook.ts`) mirrors 9a: dedupe in `stripe_connect_event`, `FOR UPDATE`, rollback + recorded message on error. **Isolation:** the agency comes only from `event.account` -> `agency_connect.stripe_account_id` (unknown => `ignored`), and every client lookup (Checkout session / `client_reference_id`, subscription id, customer) is `AND client_billing.agency_id = <that agency>`; never look a client up by id alone. Checkout sessions carry `client_reference_id = client.id`, so a paid-but-since-replaced link still resolves; the billed price is read from Stripe (`unitAmountCents`), not the event. Signals pass `eventAt` (R3 guard via `last_stripe_event_at`) and the transition table ignores untracked subscriptions (R11). **M8:** `checkout_completed` uses `isSubscribed(row)`; a second live subscription is ignored (tracked id kept, event `ignored`) and queues agency notice `client-duplicate-subscription` (dedupe `client-duplicate-subscription:<clientId>:<subscriptionId>`). `invoice.paid` resumes only `paused_by='auto'` clients via `liftAutoPause(tx, clientId, actor)` (`client-pause.ts`, shared with daily reconcile; swallows `billing_seat_limit` and `service_paused` (15c-3 hold) -> 'refused', payment still recorded, one neutral warning). Notices: `noticeAudience(kind)` - `client-paid`/`client-payment-failed`/`client-auto-paused` go to the agency, `client-payment-link`/`client-payment-needed` to the client; `payment_failed` queues both. Stripe calls after the commit (expire superseded session) are best effort. Dispute events carry only a charge id: `getConnectedCharge` finds the customer. `STRIPE_CONNECT_WEBHOOK_SECRET` is separate from the 9a `STRIPE_WEBHOOK_SECRET` (different Stripe endpoint).
  **R15:** `account.updated` only identifies the account; the webhook persists `gw.getAccount` (live) values via the shared `connectStatusFor` (also used by `get_connect_status`), so out-of-order deliveries cannot regress state. **R16:** a Checkout with `payment_status: 'unpaid'` (async methods) tracks customer + subscription but stays `invited` (no `last_paid_at`, no notice); the first `invoice.paid` activates (and sends `client-paid`), `invoice.payment_failed` moves it to `payment_needed`. Other lift errors fail the event for retry. The billed price is never recorded as 0.
- **Final-wave rulings (9b R19–R26).**
  - **R19:** decided refusal copy is thrown as `new ToolError(code, msg, { userFacing: true })`; `toFormResult` and MCP `mapError` show it whatever the code (a plain `conflict` keeps the generic concurrency copy, a plain `internal` still reaches the error page). Agency Stripe failures: `internal` + "Stripe couldn't complete that. Please try again."; the client's portal failure keeps its platform-free copy.
  - **R20:** Checkout prices resolve at creation: a stored client price is reused only when it is the current default or still active (`getConnectedPrice`); otherwise the CURRENT default. Never check out an archived old default (defaults archive the previous price).
  - **R21:** `isSubscribed(row)` includes `invited` + tracked subscription (R16, async first payment processing): disable cancels at period end and keeps tracking; resend / price change / a racing re-invite refuse "This client's first payment is still processing."; the R16 branch keeps `checkout_session_id`.
  - **R22:** auto-pause fires once per failure episode: `client_billing.auto_paused_failure_at` = the paused episode's `payment_failed_since`; a manual resume sticks until a new failure. Candidates are re-checked under `FOR UPDATE` (`payment_needed`, `enabled`, cutoff) inside the pause transaction.
  - **M3:** daily reconcile -> `active` also calls `liftAutoPause`, sets `last_paid_at` only when the Stripe status is `active` (not `trialing`) and queues `client-paid` on the first payment; `ConnectDailyResult.resumed` triggers `syncSeats` like `paused`.
  - **R27 (7b2):** `disable_client_billing` re-checks the row `FOR UPDATE` in its transaction; if it tracks a subscription the call did not cancel (live agencies) it refuses `conflict` with `JUST_PAID_MESSAGE`.
  - **Discount cap (7b2):** `discountRedemptions`/`discountExhausted` (`discount.ts`) = agencies currently holding the coupon (`attached_coupon_id`, excluding the redeemer); `couponFor` and `redeem_discount_code` lock the `discount_code` row `FOR UPDATE`, reserve under the lock and restore the previous coupon (compare-and-set) if the Stripe attach fails; exhausted reads as `invalid_code`. Stripe's `max_redemptions` stays final; `attach_agency_discount` (staff) ignores the cap.
  - **Reconciliation:** an unreachable account (`account_invalid` / permission error, see `isAccountUnreachable`) stops that agency's run (ids logged) and cancels nothing; only `resource_missing` on a subscription cancels the row.
  - **R23:** a webhook that lifts an auto-pause runs `syncSeats` after the commit (best effort).
  - **R24:** admin disconnect keeps `stripe_account_id` (reconnect = new account link for the same account, product/price/portal config kept); only `account.application.deauthorized` clears it and the objects on it (`forgetConnectedAccount`).
  - **R25:** "Manage payment" uses a Customer Portal configuration on the connected account (`createConnectedPortalConfiguration`: payment method update + invoice history, no cancel), stored in `agency_connect.portal_configuration_id`; created on the first defaults save (best effort) or lazily by `open_billing_portal` (`ensurePortalConfiguration`).
  - **R26:** `get_connect_status` persists live account values when they differ (not under `ctx.support`, never over a disconnect); a disconnect also sets `client_billing.enabled = false` on every row.
- **Reduced trial (Phase 10 f12).** `isReducedTrial` = `trialing` AND NOT `seat_cap_exempt` AND `agency_onboarding.source = 'open'` (no onboarding row = not reduced) → `maxActiveClients = TRIAL_ACTIVE_CLIENTS` (1), refusal `reducedTrialMessage` (userFacing `billing_seat_limit`). The SQL twin `agencyReducedTrial` (`@cs/db` filters) slows `claimDuePages` daily pages to 7 d when every tracking agency is reduced; keep the two in sync.
- **Agency hold (15c-3a).** `agency.suspended_at` => `billingAccess().onHold`, which beats any Stripe state in `assertAgencyServiceable` (`service_paused` + `holdMessage(role)`). `assertCanActivateClient`/`resumeClient` refuse `service_paused` on hold; `connect-webhook`'s system `resumeClient` tolerates it (the auto-pause stays until the lift). `syncSeats` and `runBillingDaily` skip held agencies (incl. `runConnectDaily`); the daily stat is still written with MRR 0. No deadline shifts on lift (A9): hold time counts.
- **Hold collection (`hold.ts`).** `applyHoldCollection`/`pauseIfHeld` run only after commit and never change subscription `status`. `applyHoldCollection` records `admin_hold_billing_ok|_failed` events (`holdBillingIssue` reads the latest, drives Retry); `pauseIfHeld` writes only failures. Callers: `webhook.ts` post-commit step (new platform subscription) and `connect-webhook` `PostCommit.pauseHeldFor` (`checkout.session.completed`). Stripe `resource_missing` on pause/resume is still a permanent `_failed` (backlog).
