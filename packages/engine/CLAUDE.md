# @cs/engine — working notes
Change-detection pipeline (diff, tag, events, scoring, moves, prices, reviews) plus briefs, alerts, reports and the delivery outbox.

## Gotchas

### Pipeline & stages
- **Engine needs `OPENROUTER_API_KEY`** (embeddings + LLM fallback); without it `engine-sweep` skips and captures don't enqueue diffs. Jev runs through the same key (OpenRouter `typesafe/jev-1.14`); when Jev is down decisions fall back to the LLM.
- **Retries:** a failed stage is re-offered by the 5-minute `engine-sweep` only after 30 × 2^(attempts−1) minutes; after 5 attempts (~7.5 h) it is exhausted and logs `[engine] stage … exhausted`. To re-run an exhausted subject, delete its `stage_run` row (service role) or bump the stage version.
- **Engine queues use the `short` pg-boss policy with a per-subject `singletonKey`:** at most one *queued* job per subject (capture/change/event/client); a subject still queued from the previous sweep is not enqueued again.
- **Money changes are never masked (spec §6.1):** any detected price/percent change always forces a web diff to be flagged and a tag result to be `meaningful`, regardless of volatile-block masking, model confidence or what the LLM/Jev decision answered — see `gateChange` in `src/web/diff-stage.ts` and the `forced`/`money` logic in `resolveTag` (`src/tag/questions.ts`). Date- or duration-only changes are still detected but can be dismissed as cosmetic; a low-confidence dismissal also writes a `decision_review` row.
- **Vendor captures diff only after a 10-minute settle delay:** collectors write ad/review/job/GBP rows *after* the `capture` row, so the structured-diff stage refuses to claim a capture younger than 10 minutes and the sweep skips it until next time.
- **Rank changes/events are tenant-private:** `rank_change` is the one `ChangeType` that is never global — its `detected_change`/`event` rows always carry `agency_id` **and** `client_id` (CHECK-enforced), are scored only for that client, hidden from other tenants by RLS, and never cross-channel merged.
- **`detected_change.status` also takes `superseded` and `suppressed`:** `superseded` = an older stage version's output once a newer version re-diffs the same subject (its event loses that evidence link and is retracted once no live evidence remains); `suppressed` = the churn guard's catch-all for non-money changes on a churned page (capped at `CHURN_SUPPRESSED_MAX` = 200, flag `churn`). Neither is ever tagged or scored — no `decision_review`/`event` row.
- **A review's stage subject is `md5(review_id || '|' || text)::uuid`:** editing a review's text makes it new work for `review_themes`, but `review_analysis`'s PK is `(review_id, vertical_id)`, so the fresh analysis's `onConflictDoUpdate` replaces the old row in place (no orphan).
- **Complaint-spike (`review_spike`) changes have `stage_version: 1` and no `stage_run` row:** written directly by the nightly `runReviewInsights` job (idempotent via a 30-day per-topic cooldown), not the `stage_run` claim mechanism.
- **Re-ask (`reaskReview`, sweep `reask` list):** `review_analysis.checked_at` is the re-ask marker (set even when nothing new is found); a row is re-asked only for topics added/changed since, or when its stored `textSha` is stale (then re-analysed as (b)). Window 180 d, Jev first, at most `REASK_DAILY_MAX = 2000` reviews/day (daily count = `DISTINCT review_id` with `checked_at` today), only when no new reviews are pending. Jev and LLM both down means the review is re-offered every sweep (no backoff).
- **Price spans never end on an out-of-order capture:** `price_extract`'s watermark is the page's newest capture with a **done** stage run; an older capture is a no-op, and a capture whose priced blocks exceed `PRICE_MAX_BLOCKS` (40) ends no spans either — `price_point.ended_at` won't reflect every capture in real time on catalogue-sized pages.
- **`resolveDecisionReview`:** user-fixable refusals are `invalid_input`; it locks the change row `FOR UPDATE` before claiming the review (same order as `supersedePriorChanges` — no deadlock).

### Briefs
- **Statuses:** `generating → ready → approved → sent`, or `failed`; one brief per (client, delivery Monday). Failed briefs retry hourly up to `BRIEF_MAX_ATTEMPTS = 3`; a `generating` row > 30 min is re-claimable and `attempts` is a fencing token. `brief-once [--starting-point] --force` deletes the unapproved brief/starting point first.
- **Nothing unverified is ever stored as `ready`:** a writer failure, unparseable draft or verifier outage (Jev *and* LLM failing) fails the attempt; an unsupported sentence is dropped, a failed headline drops the item, and a brief with nothing left is `kind = 'quiet'` ("No significant competitor moves this week."). Never store model text without `verifyDraft`/`verifyText`. Below-threshold support answers count as unsupported and are never queued to `decision_review`.
- **Deterministic number rules are kind-strict:** money ↔ money, plain ↔ plain, percent within ±1 point of an evidence percent; the period's year is allowed. "69 dollars" (no `$`) is dropped. Word numbers and weekdays are not checked.
- **Featured events are never re-gathered:** an event in an item of one of the client's non-failed briefs is excluded from every later gather, and a move absorbs its own events.
- **Move summaries are context, never evidence:** `candidateEvidenceText` holds only live event summaries/change texts; `candidateContextText` adds the move's "Detected pattern" for the writer only. All-retracted moves aren't gathered; items citing no events are refused; `approveBrief` drops items retracted after `ready`. Gather windows on `event_score.scored_at`.
- **Writer and verifier take the period** (`Brief period: <start> to <end>.` heads verifier evidence; its dates are allowed dates, never numbers). Move recommendations use first detection → now. One live recommendation per move; a failing move-recommendation title falls back to the playbook title.
- **Brief review writes lock the brief:** each AM write transaction takes `SELECT … FOR UPDATE` on the brief and re-checks `status = 'ready'`; reorder permutes the active items' existing `ord` values (unique `(brief_id, ord)` DEFERRABLE INITIALLY DEFERRED, migration `0030`), so ords need not be 0-based or contiguous — always sort by `ord`.
- **Prompts escape every untrusted string:** competitor names (scraped GBP titles), the rendered playbook line, the client-context block and all evidence text pass `escapeEvidence` inside tagged blocks; system prompts say never to follow instructions in them.
- **`summary`/`kind` are recomputed twice:** at AM approval (`approveBriefTx`) and again by `deliverBrief` in its own locked transaction right before `finalBriefSummary`, because evidence can be retracted in between (`dropRetractedItems` runs both times). Don't assume the approved summary is accurate at send time.
- **`dropRetractedItems` also dismisses recommendations:** at approval and delivery, a dropped item's `recommendation` still `todo` is dismissed (`dismiss_reason: 'Evidence withdrawn before delivery'`, `system` feedback); `in_progress`/`done` ones are left alone.
- **PDF catch-up:** a `sent` brief/report with `pdf_key IS NULL` is re-enqueued within 7 days (`PDF_CATCHUP_DAYS`) only when the whole hours since `sent_at` is a power of two (`PDF_RETRY_HOURS`: 1, 2, 4 … 128 h, ≤ 8 renders; stateless). Move recommendations back off per move (`rec_attempts`/`rec_retry_after`, 1, 2, 4, 8, 16 d, give up after 5; only AI outcomes count). Topic-discovery batches write a `pending` `model_batch` row before the provider submit (swept to `failed` after 60 min); apply is one `FOR UPDATE` transaction gated on `status = 'submitted'`.

### Runbooks (`src/runbook/`)
- **`loadClientRunbook` order (R2):** client runbook → legacy (pack plays + `playbook_override`) if the agency has overrides → agency runbook only when `packUsesGenericPlays` (catalogue types without own plays; HVAC/dental stay legacy) → legacy. No `generic` dep → agency step skipped.
- **Thresholds (R3):** `client.score_thresholds` → agency knob → platform knob → pack routing. A set column always lives in a customised `knob:thresholds` (`withColumnThresholds`; `set_alert_rules` writes both). Tier limits (R5): client → agency knob → null. Focus areas only re-order (`selectBriefItems`).
- **Items:** `play:`/`self_rule:`/`knob:` keys; `version` bumps per write; children keep `upstream_version`/`upstream_snapshot`; `customised` = differs from snapshot. Invalid stored items are skipped with a warning.
- **The platform runbook is seeded once from `generic.yaml`:** later generic/pack additions do NOT reach existing runbooks (needs a sync step).
- **Pending never sticks:** skipped/failed stamps; `get_runbook` reads pending > 10 min as failed.
- **Tailoring:** one `runbook_tailor` call (via `redactForModel`); keeps only title/template/area ids that pass `applyTailoring`, else the base. Base = `copyItems(agency)` for generic packs, else `legacyClientItems`. Tailored rows are not `customised`.

### Alerts & delivery
- **`deliveryConfigFromEnv` returns `null` unless both `APP_URL` and `LINK_SIGNING_SECRET` are set;** then the 8 delivery jobs (`alerts-sweep`, `alert-process`, `alerts-digest`, `notify-dispatch`, `briefs-deliver`, `brief-pdf`, `reports-quarterly`, `report-pdf`) idle with a start-up warning naming the missing variables.
- **The outbox row is written in the same transaction as the state change that causes it** (alert release, brief going `sent`, withdraw): a rollback never leaves a stray message and a commit never drops one. Keep this for any new delivery-triggering write.
- **Lock order: `lockClientAlerts` before any alert row lock:** every alert write path (sweep, release, approve, dismiss, digest, withdraw) takes the per-client advisory lock first, then row locks — or risk deadlock against the sweep/throttle.
- **`in_app` notification rows are inserted already `sent`:** they *are* the inbox (the UI sets `read_at`); only `email` and the reserved `sms` go `pending → sending → sent | failed`. Quiet hours defer `email`/`sms` only; agency webhooks ignore personal quiet hours.
- **Withdrawn alerts free their merged events:** `withdrawAlerts` deletes every `alert_event` row except the alert's own primary, so merged events are picked up fresh by the next sweep.
- **The dispatcher re-checks liveness right before sending:** `dispatchDue`'s `undeliverableReason` (contact still active; for `alert` rows the alert exists, is not `withdrawn`/`dismissed`, and its primary event is not retracted) fails a stale row once, permanently, instead of retrying.
- **Webhook URLs are re-checked at send, not only at save:** `https`-only, allowlist `hooks.slack.com`/`.webhook.office.com`/`.logic.azure.com`/`.environment.api.powerplatform.com`, no redirects followed — in case DNS now resolves elsewhere.
- **The root barrel imports `node:crypto`** (`structured/rank.ts` `rankSettingsKey`): client components never import `@cs/engine`; shared pure math (geo projection) lives in `@cs/core`.
- `postWebhook` is the only webhook POST path (the Slack/Teams host allow-list `webhookUrlProblem`, not the SSRF guard; no redirects; timeout 10 s in the outbox sender, 5 s for `test_webhook`); the sender and `test_webhook` both use it.
